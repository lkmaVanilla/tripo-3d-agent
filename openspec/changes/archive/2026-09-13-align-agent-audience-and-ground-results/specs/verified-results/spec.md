## Purpose

让正式结果中的交付状态、技术数据和执行事实均能追溯到本请求的持久化证据，防止模型自由解释与真实报告相互矛盾。原始 Agent 提议继续用于追踪和独立评测，接口兼容现有网页，历史记录不足以支持的结论必须明确保留不确定性。

## ADDED Requirements

### Requirement: 正式结果以实测证据为依据

系统 MUST 根据本请求的已保存状态、交付资产引用和技术报告生成正式结果。面数、体积、检查项及上限 SHALL 来自实际报告，不得用生成参数、模型自由文字或供应商成功状态替代；正式结果 MUST 不宣称未执行的绑定、动画或未检查的类别、风格与外观符合性。

#### Scenario: 正确引用附带错误解释
- **WHEN** 模型引用技术通过的本请求资产，报告为 2,645 个三角面，但模型解释声称只有 1,000 面且绑定、动画已经完成
- **THEN** 正式结果采用 2,645 面和真实检查范围，不包含这些虚构事实，原始错误提议仍可在脱敏执行记录中追踪

#### Scenario: 无法获取可信面数
- **WHEN** 已下载文件无法解析或不在技术检查支持范围内
- **THEN** 正式结果指出文件检查失败及面数无法验证，不把缺省零值当作实测面数，也不据此宣告面数达标

### Requirement: Agent 决策与事实核验分离

Agent SHALL 保留交付或结束请求的选择与原始说明。Runtime MUST 校验交付引用属于当前请求且通过既定技术检查；Agent 选择结束仅能证明其作出结束决定，原始说明不得自动成为系统已核验的停止原因。

#### Scenario: 无效交付引用
- **WHEN** Agent 提议交付不存在、属于其他请求或未通过检查的资产
- **THEN** 系统拒绝交付，不设置成功终态或该交付引用，并保留提议与拦截证据供评测

#### Scenario: 尚有额度但 Agent 结束
- **WHEN** Agent 选择结束，原始解释声称预算耗尽或所有方案都不可行，但持久化证据不能证明这些说法
- **THEN** 系统可以接受其结束选择，正式结果只说明 Agent 结束了请求、是否交付及可核验的现有结果和额度，不认证这些停止理由，也不额外调用模型判定说明真伪

#### Scenario: 结束说明声称成功
- **WHEN** Agent 选择不交付，却在原始说明中宣称已经成功完成全部制作
- **THEN** 正式结果保持未交付，不因该文字改变执行状态或选中交付资产

### Requirement: 各终态准确表达已知范围

系统 SHALL 依据实际终止来源与执行证据区分检查未通过、无法验证、操作失败、提交结果未知、预算限制、Agent 结束、用户停止、期限到期及恢复不可用。本地执行终止 MUST 不被解释为远端任务已取消；预算耗尽与是否存在合格交付证据 MUST 分开判断。

#### Scenario: 提交结果未知
- **WHEN** 生产提交可能已被远端接收，但尚无可确认的任务 ID
- **THEN** 正式结果说明远端接受情况未知，保留已消耗额度，不声称远端生成明确失败或已取消，也不自动重发

#### Scenario: 用户停止或执行到期
- **WHEN** 用户停止或请求超过适用期限，且远端任务没有明确的取消证据
- **THEN** 正式结果说明本地执行已结束，保留已知任务和已有产物，不声称远端已取消；执行到期和生产前空闲到期按各自持久化期限表达

#### Scenario: 模型额度耗尽后的交付
- **WHEN** 模型额度耗尽，但已有本请求合格产物，且尚未停止或超过执行期限
- **THEN** 系统按既定规则依据报告交付，并明确由程序完成收尾；没有合格证据时不宣告交付，已知任务仍按原规则继续确定性处理

#### Scenario: 已知任务恢复后完成
- **WHEN** 系统在原期限内恢复已知任务并取得检查结果
- **THEN** 正式结果仅引用该原任务的产物、报告或已记录失败事实，区分恢复收尾与新模型决策，不宣称重新生产或额外纠偏已发生

### Requirement: 结果与终态一致提交

系统 MUST 将新终态、正式结果依据、交付引用与相应结束记录作为一致的持久化结果保存。最新停止和期限判断优先，重复收尾或迟到回调不得覆盖既有终态；结果生成不得增加模型调用或生产副作用。

#### Scenario: 停止后成功回调到达
- **WHEN** 用户停止已经生效，较早启动的生产或 Agent 成功结果随后到达
- **THEN** 请求仍保持停止，正式结果不变为交付；已有产物按原规则保留，预算和期限不被重置

#### Scenario: 收尾写入失败或重复执行
- **WHEN** 收尾持久化失败，或者进程退出后同一收尾逻辑再次被执行
- **THEN** 系统不发布与持久化状态矛盾的成功结论；重试或恢复不重复产生终态业务效果，也不新增生产

### Requirement: 输出接口共享正式结果并保持网页不变

系统 SHALL 通过现有会话字符串结果和兼容的状态字段向普通接口、WebSocket 与 JSON 导出提供一致的正式结果。页面固定展示文案、布局和交互 MUST 保持不变；后端动态结果可以按本规格更新。原始模型说明和外部错误正文 SHALL 保留为有来源的脱敏证据，不混入程序核验的事实正文。

#### Scenario: 多个入口读取同一终态
- **WHEN** 有权限的访客通过会话接口、WebSocket 重连或执行记录导出读取同一请求
- **THEN** 各入口的正式结论、交付引用和技术数据一致，原始提议仍作为独立证据存在，既有网页无需修改即可显示结果

#### Scenario: 当前页面继续使用
- **WHEN** 更新后的后端向原有页面提供请求结果
- **THEN** 页面标题、固定介绍、输入示例、按钮及交互保持原样，仍可展示状态、动态结果、报告与时间线，不要求新增页面组件或更换结果字段类型

### Requirement: 历史说明不得冒充已验证事实

系统 MUST 区分历史自由解释与按新规则生成的结果。历史状态、报告和引用足以支持的事实 SHALL 可被保守重建；证据不足时 MUST 明确说明不足，且不得将缺乏证据的交付或检查项标为技术通过。此处理不得覆写原始说明、报告、历史事件、预算或期限，不得为补充说明重新调用模型或生产。

#### Scenario: 历史记录有完整交付报告
- **WHEN** 历史终态没有新结果版本，但有正确的交付引用和完整技术报告
- **THEN** 正式输出可根据已有报告生成并标明历史证据来源；旧解释作为未核验的原始说明保留，不伪造当时运行过新版核验

#### Scenario: 历史完成记录缺少证据
- **WHEN** 历史状态声称完成，但交付引用缺失、报告缺失或不能证明技术通过
- **THEN** 正式输出说明历史交付证据不足，本次交付状态及无据候选不标记为技术通过；原始状态、说明和报告保留为历史证据，不改变既有终止时间、清理期限或启动新执行，也不抹除另一个具备完整证据的候选自身的技术检查结果

### Requirement: 正式结果核验不代替 Agent 评测

系统 SHALL 分别核验正式结果的证据一致性和保留 Agent 原始提议的评测材料。Runtime 拦截成功或程序生成正确结论 MUST 不被计作原始模型解释已事实正确；未实施的自由文本语义核验 SHALL 标为无法验证，既定 20 案例各 3 次的独立 Agent 验收要求保持不变。

#### Scenario: 程序纠正了公开结论
- **WHEN** 原始模型说明含错误事实，而正式结果仅展示程序能够支持的事实
- **THEN** 单次结果核验只确认其证据范围，不宣称模型解释已通过语义核验；原始错误说明仍能用于独立案例评测，受控测试或本变更的小样本记录不计作完整 Agent 验收通过
