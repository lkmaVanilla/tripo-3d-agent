## Why

当前生产客户端固定访问 Tripo 国际站，ECS 排查中观察到国际站连接失败，而国内站可到达；同时提交错误在客户端和执行层被逐层简化，导出记录不足以解释失败发生在哪一步。用户已决定全量使用国内站并放弃旧历史，需要完成接入、可追踪的失败记录及真实链路验收，同时保留“未知提交不自动重试”的既有保障。

## What Changes

- **BREAKING**：增加 `TRIPO_BASE_URL`，默认地址由 `https://openapi.tripo3d.ai/v3` 改为 `https://openapi.tripo3d.com/v3`；ECS 显式配置国内地址与匹配的国内 API Key。一次部署使用一个站点，不自动切站或回退国际站。
- **BREAKING（本次发布的运维操作）**：按用户授权，停服并备份本项目旧运行数据后，清空旧会话、执行、checkpoint、资产版本和模型文件，以空数据启用国内站。旧国际任务不迁移、不追踪、不恢复；不声称已经取消供应商任务或删除供应商数据。此操作不成为启动时自动清理逻辑，也不改变正常升级保留历史的约定。
- 增加显式、只读的国内站接入预检，使用部署进程实际生效的配置验证余额接口的网络与鉴权。Key 已填写、HTTP 可到达或进程存活均不等于鉴权成功。
- 补齐提交、查询、上传、下载各阶段的结构化诊断：错误分类、耗时、尝试次数、HTTP 状态、供应商错误码、可用的 `X-Tripo-Trace-ID` 及执行关联身份；保留中间重试失败，统一脱敏后写入执行证据与服务器日志。
- 页面展示可理解的失败原因及处理状态，执行 JSON 导出保留详细证据；重连和重新读取共享同一已持久化事实，不在普通聊天中展示内部堆栈、凭证或供应商敏感材料。
- 保留提交前记账与持久化、已知 TaskID 继续查询、未知提交停止且不自动重发的现有规则；补充异常响应、HTTP 重定向、诊断写入失败及崩溃恢复等回归验证。诊断精度提高不构成重新提交的授权。
- 国内站鉴权通过后，在 ECS 完成一次真实文本生成和同会话一个真实减面目标，允许在既有预算内依据不达标技术报告自动纠偏并逐次保留证据，验证上传、异步查询、下载、技术检查、版本来源、网页预览及证据导出；故障与防重复提交使用受控测试验证。

### Scope and Non-goals

本次修复服务于现有静态资产连续创作链路，遵循 `PROJECT_BRIEF.md`、`CONTEXT.md`、ADR 0009、0010、0017、0019、0022、0023。保留可选面数／体积约束、单 Agent 决策、预算、匿名会话隔离和并发规则。

当前已经使用 Tripo **V3 API**，文本生成模型为 **H3.1（`v3.1-20260211`）**，减面算法为 **`v2.0`**；本次不进行 V2 到 V3 API 迁移，也不把减面算法版本改成 `v3`。DeepSeek `deepseek-v4-pro`、Skill 与执行协议 V4 均不升级。

不增加多供应商或多区域路由，不新增绑定、动画、图片输入、模型导入或通用监控平台；不新增未知任务恢复、自动重提或一键生产重试；不修改网页定位和宣传文案；不增加视觉检查，也不以本次冒烟验收替代完整 Agent 案例集评测。

## Capabilities

### New Capabilities

- `tripo-provider-access`：统一的 Tripo V3 地址配置、国内站只读接入预检、单站点发布切换，以及生产请求不得隐式重发的客户端约束。
- `provider-diagnostics`：跨提交、查询、上传和下载的结构化错误证据、逐次尝试记录、脱敏边界及诊断失败时的执行一致性。

### Modified Capabilities

- `chat-asset-workspace`：扩充逐执行结果与证据展示，明确失败原因、未知提交状态和页面／重连／导出的一致性。

现行 `checkpoint-recovery` 的“生产恢复沿用原操作”等要求继续生效，本次对其补充实现验证，不重写其恢复合同。

## Impact

- 配置与 Tripo 适配层：`internal/app/types.go`、`internal/app/service.go`、`internal/tripo/`、`.env.example`，以及部署预检入口。
- 执行与证据：生产、上传准备、有限重试、事件持久化、终态说明、HTTP／WebSocket／导出脱敏与服务器日志；不另建任务系统或日志数据库。
- 网页：现有操作错误和结果证据区域的针对性调整，不更改工作台结构和产品展示文案。
- 部署：`tripo-agent.service` 的有效配置、本项目实际 `DATA_DIR` 的一次性备份和重置、国内站真实链路验收。最近排查中国内余额接口曾返回 401；用户已表示更换 Key，实施时仍须重新验证实际生效的凭证，不能把鉴权视为已通过。
- 测试与文档：配置、协议、错误投影、重试／恢复及页面证据回归；发布操作说明和有清晰范围的验收报告。
- 基线依赖：`make-asset-limits-optional` 已实现但尚未归档，本提案以其实现及 ADR 0023 为基线。本次不归档该变更，不修改它的 delta 或主规格，也不覆盖其 `verified-results` 修改；后续同步规格时需分别保留两次变更。

以上均为待实施范围。提案完成和 OpenSpec 校验通过不代表代码已经修复、线上已切换或真实模型链路已通过。
