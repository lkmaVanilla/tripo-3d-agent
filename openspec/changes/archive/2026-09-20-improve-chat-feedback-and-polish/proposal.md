## Why

首页输入示例仍写着“最多 5,000 个三角面”，与新版聊天的可选验收上限容易混淆；消息被接受后，聊天区域缺少持续反馈，用户难以区分 Agent 正在处理、等待制作或连接中断。当前部分辅助文字偏小，需要在保留既有工作台结构的前提下改善阅读和操作体验。

## What Changes

- 将首次输入示例改为资产用途、造型和材质描述，移除预置的面数上限示例；不把占位文案写入用户请求，不改用户明确提出的约束或历史记录。
- 在发送过程和聊天末尾提供连续但非持久的等待反馈，覆盖首次请求、后续目标、澄清回答后的 Agent 处理，以及排队、生成／减面和文件准备阶段。提示由现有提交状态、会话快照和事件驱动，不把整个执行过程都称为“思考中”。
- 将连接状态和快照新鲜度接入页面展示；断线或长时间没有有效快照时显示恢复进度提示，重新取得状态后再显示当前阶段。终态、停止处理中、会话切换和刷新均清理或重新推导提示，不产生重复聊天消息或生产请求。
- 保留现有布局、配色、技术信息和全部功能入口，局部调整字号、对比度、间距、卡片层级与轻量等待动画；兼顾桌面、移动端、键盘操作和减少动态效果偏好。
- 补充前端状态、连接时序和受控浏览器验收，验证有反馈、阶段准确、提示不残留、不串会话，并确认诊断、报告、版本引用和导出入口没有被移除。

### Scope and Non-goals

本提案遵循 `PROJECT_BRIEF.md`、`CONTEXT.md`、ADR 0022 的连续会话／草稿／停止规则，以及 ADR 0023 的可选技术上限。当前文本生成、静态模型减面和技术解释的能力边界保持不变。

用户已明确暂缓技术信息优化，因此本次不执行此前讨论过的“更多 → 诊断记录”重组，不隐藏生产额度、模型调用次数、TaskID、技术参数、程序核验或 JSON 证据，不精简或重写需求草案、计划及正式结果。面数、文件大小、版本来源和现有错误说明按原语义展示。

不新增后端接口、数据库字段、业务事件或状态机，不修改 Agent 提示、Skill、模型、生产预算、checkpoint、轮询规则、未知提交不自动重试规则或匿名权限。不引入 token 流式输出、新前端框架、设计系统、整体布局重做或新制作能力。不部署、不调用真实 DeepSeek／Tripo，也不重跑完整 Agent 案例集。页面样式检查仅针对网页可读性和交互，不新增 3D 产物视觉检查或视觉评测用例。

## Capabilities

### New Capabilities

无。此次是现有工作台交互的改进。

### Modified Capabilities

## Impact

- 前端：`internal/web/static/index.html`、`app.js`、`workspace-state.mjs`、`workspace-connection.mjs`、`workspace-chat.mjs` 和 `style.css`；可新增一个小型纯函数模块集中计算展示状态，避免分散判断。
- 数据来源：复用会话的活动执行身份、公开 Run 状态、操作卡和已有 `model_call`／`agent_proposal`／生产／技术报告事件，以及本页提交与连接状态。现有 HTTP／WebSocket／导出协议不变。
- 验证：扩展 `internal/web/tests/workspace.test.mjs` 和受控浏览器脚本，复用当前 Go 浏览器夹具与静态资源构建；验收说明单独记录测试范围，不以浏览器用例冒充真实 Agent 或供应商验收。
- 规格：仅修改 `chat-asset-workspace` 的增量规格，不同步或归档其他变更。已完成的 `make-asset-limits-optional` 实现与 ADR 0023 是当前基线，本次不重写其规格或历史默认值。
