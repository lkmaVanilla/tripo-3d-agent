## Context

问题与产品范围见 [proposal.md](proposal.md)。本设计依据当前 `e9414ee` 版本，目标是改善前端反馈而不改变资产制作或技术信息展示。跨状态归并、连接生命周期和 DOM 更新的协作需要在实施前明确，因此保留本设计文档。

已核对的实现事实：

| 位置 | 当前行为及设计含义 |
| --- | --- |
| `internal/web/static/index.html` | 首页示例含“最多 5,000 个三角面”；聊天容器只放正式消息，没有独立活动提示 |
| `app.js` | 发送按钮已有提交反馈，页顶有 Run 状态；连接回调只改页顶文字，未进入工作区状态 |
| `workspace-state.mjs` | 已按会话保存草稿、活动 Run、操作卡、全部接收到的事件和游标；是否能发送仍由服务端活动指针决定 |
| `workspace-connection.mjs` | 用连接代次隔离切换会话后的迟到回调，断线后 1500 ms 重读 HTTP 并连接 WebSocket；尚无快照新鲜度检测 |
| `internal/app/conversation_agent.go` 的 `conversationRunView` | 公开 Run 已包含 `current_operation` 的身份、种类、阶段和 TaskID，不需要新增后端展示字段 |
| `internal/app/conversation_projection.go` 的 `ConversationSnapshot` | 同一事务返回 Run、消息、版本和游标；事件按 Run 归属和序号返回，首次 `after=0` 可读取现有完整事件，后续补读 |
| `internal/app/agent.go` | 模型调用前记录 `model_call`，返回后记录 `agent_proposal` 或 `model_error`；单次模型请求最多 90 秒，Runner 非流式 |
| `internal/app/conversation_http.go` | WebSocket 每 500 ms 推送快照，即使没有新事件；这是连接新鲜度依据，不证明模型或供应商工作正在前进 |
| `workspace-chat.mjs`、`style.css` | 消息复用节点并保留展开项，接近底部才跟随滚动；正文约 12–13 px，若干辅助信息降至 8–10 px |
| `internal/web/tests/` | 已有 Node 状态／连接测试、HTTP/WS 全拦截的浏览器测试和仅连接本机受控 Go 服务的浏览器测试 |

`running` 同时覆盖 Agent 决策和供应商执行，不能直接映射为“思考中”。供应商成功后到文件登记之间没有分别表示下载和解析的完整公开阶段，页面不得发明这两个子阶段的精确进度。

## Goals / Non-Goals

**Goals:**

- 用一处可测试的展示计算，统一发送、执行阶段与连接健康的反馈。
- 从接受请求到结果出现保持可理解的反馈，并在恢复、切换和终态时正确清理。
- 保持正式消息和临时提示分离；只调整新增反馈和现有样式。

**Non-Goals:**

- 不建立第二套执行状态机。前端不修改可发送权限、生产状态、期限、恢复或重试规则。
- 不新增 Go 生产代码、公开接口、存储字段或状态事件；不重写正式结果，不修改或迁移诊断入口。
- 不展示 token 流、模型推理正文、倒计时或估算生成完成时间，不新增页面遥测和持久浏览器缓存。

## Decisions

### 1. 只调整当前首页占位示例

建议文案为：“例如：制作一把用于产品展示的低模木椅，轮廓简洁、木质纹理自然。”它只存在于 `placeholder`，不是默认输入值，也不进入请求组装。

不做全仓库“5000”替换。历史演示、测试中主动填写的面数、旧协议以及当前用户明确提出的限制均保持原状。相比把旧上限换成另一个数字，移除数字示例不会继续暗示默认验收门槛。

### 2. 集中计算展示状态，复用已有快照与事件

新增小型 `workspace-activity.mjs`，或在现有状态模块内提供等价的纯函数。输入为当前工作区、提交状态、连接状态；输出为提示类别、文字、动画标记和可选真实进度，内部可携带 Run／Operation 身份用于归属校验。该函数只决定展示，不发送请求或修改业务状态。

展示分两层：先判断提交／连接／停止等覆盖状态，再计算当前 Run 的阶段。

1. 会话不可用、正在加载或首次进入：清理旧忙碌提示，按已知事实显示不可用或读取中。
2. 当前消息仍在提交或接受情况未知：显示发送中／送达待确认；首次输入留在首页，后续输入在聊天末尾反馈。即使旧 Run 或旧问题还在，也不能宣称新消息已经开始处理。
3. 当前停止请求尚未返回或已接受但 worker 未退出：显示停止处理中；如果停止请求失败，按既有错误反馈及重新读取状态恢复展示，不清空草稿。
4. 服务端没有活动 Run：不从最近历史 Run 推导忙碌状态。已确认终态始终保持终态；若活动指针暂未释放，用“正在结束本次执行…”表示退出窗口，不恢复思考或提前解锁发送。
5. 对仍活动的 Run，连接在重连、数据过期或重新同步时优先显示连接反馈，再依据有效快照展示下表阶段。等待用户回答时保留问题，连接提示只解释状态更新情况。

| 事实依据 | 主活动提示 | 显示约定 |
| --- | --- | --- |
| 当前 Run 为 `understanding`，或有尚未闭合的最新模型调用且没有更后的制作／待答／终态事实 | 思考中… | 覆盖首次理解、澄清之后以及工具结果之后的模型处理 |
| `awaiting_answer` 且具有有效问题身份 | 等待你的回答 | 静态文字，无思考动画；原问题和回答入口保持 |
| `queued` | 排队中… | 表示本地等待名额，不提供队列位置或预计时间 |
| `queue_full` | 当前繁忙，请稍后重试 | 使用已有入队按钮，不增加自动重试或制作入口 |
| 当前操作 `ready`，或该操作的输入准备／提交事件表明尚未取得任务身份 | 正在准备模型制作… | 不将“提交中”解释为供应商已接受 |
| 当前操作 `submitted`，供应商为等待态 | 模型任务排队中… | 区分供应商排队和本地等待名额 |
| 当前操作 `submitted`，供应商正在处理 | 正在生成模型…／正在优化模型… | 根据操作种类选择文案；沿用卡片的真实百分比 |
| 当前操作供应商 `success`，尚无对应技术报告 | 正在准备模型文件… | 统一覆盖获取、检查和登记；不显示猜测的下载／检查百分比 |
| 当前操作已结束或存在技术报告，但 Run 尚在继续 | 思考中…或正在处理… | 有新的模型调用才显示思考；否则用中性反馈，不将旧候选当作本次终态 |
| 旧数据或未知状态无法细分 | 正在处理… | 不猜测工具名称、产物成功或剩余时间 |

事件只读取种类、序号、所属 Run、操作身份和安全状态字段，不解析模型自由文本或错误字符串来判断阶段。依据 `active_run_id` 定位 Run，依据 `current_operation.id` 定位操作；模型调用以 `model_call` 与后续 `agent_proposal`／`model_error` 的序号关系辅助判断，不能让旧调用覆盖较新的工具状态。操作卡只作为同一操作的补充信息，不能使用“最后一张卡”代替身份匹配。实施核对发现卡片的 queued/running 可能沿用本地入队状态，因此远端排队/生成必须以当前操作的 tripo_progress 为依据；缺失该事件时使用中性提示，success 可补充文件准备状态。

同一 Run 的纠偏会产生新操作，必须切到新操作的事实；上一候选失败仅影响其原卡片。陌生阶段、缺少事件或历史信息不完整时降级为中性提示，不新增后端补全接口。

方案比较：单纯 `running → 思考中` 无法区分生成；从结果正文剔除字段会与本轮不调整技术信息的范围冲突；新增后端展示协议对这次需求没有必要。采用现有结构化字段加纯展示计算。

### 3. 连接新鲜度是页面事实，不是任务超时

连接模块向 `app.js` 提供结构化的内部生命周期通知，携带会话、连接代次和连接状态；页面不再通过匹配中文连接文案反推状态。这只调整浏览器内的回调，不改变 HTTP／WebSocket 载荷。每份身份正确且未落后于已应用游标的快照更新接收时间；相同游标的快照有效，不能只在新事件到来时续期。

实施采用 **15 秒未收到有效快照**作为页面同步过期的初始值，它是明确的工程默认值，不是用户制作时限。只维护当前连接的一只新鲜度计时器；触发后显示“进度连接中断，正在恢复…”，关闭旧连接并复用既有只读刷新及 1500 ms 重连路径，不另建轮询通道，不发送任何制作 POST。

WebSocket `onopen` 仅证明连接打开；当前代次取得有效快照后才恢复实时阶段。新鲜度只表示页面近期得到状态，不能证明 Agent 没有卡住，也不能触发业务失败、停止或生产重试。对已确认的终态／空闲会话，网络变化仍可显示在连接区域，不重新产生制作忙碌动画。

回调同时校验会话、代次和当前 socket 身份，避免同一会话重连后旧 socket 的迟到消息重新覆盖状态。关闭、切换、返回首页和不可访问时清理重连及新鲜度计时器；后台标签页回到前台时重新检查接收时间，过期则同步状态。时间与计时器支持注入，以受控测试推进，不用真实等待 15 秒验证。

相比一直旋转的动画，这个机制能区分页面失联与仍有有效快照的长任务；相比给模型增加新超时，不改变既有 90 秒请求限制或执行预算。

### 4. 临时提示独立于正式聊天 DOM 与持久数据

在聊天列表之后、同一滚动区域内增加一个独立活动节点；首次请求未接受时使用首页已有发送反馈区域。活动节点不参与 `sortedMessages`、消息序号、对话导出或消息数量统计，整个工作区最多一个主活动提示，原有操作卡仍承担其详细进度。

状态变化更新文字与动画标记，相同状态不重建节点；进度数值由现有卡片展示，主提示避免重复播报每个百分比。使用 `role="status"`／温和的 live 提示，动画元素对辅助技术隐藏，仅在阶段变化时更新可读提示。减少动态效果偏好下显示静态标记与文字。

沿用当前接近底部才跟随的滚动策略，将活动节点高度纳入同一次布局计算。上翻历史时不强制滚到底部，输入框和证据展开项不因刷新丢失焦点；刷新、切换版本和状态更新也不得改写输入引用或预览选择。不用定时追加“还在思考”消息，也不生成虚假 Agent 正文。

### 5. 样式只做可读性与层级调整

保留现有浅色绿色调、会话导航、桌面聊天／模型双区和移动端切换方式。实施以聊天与输入正文 **14–15 px**、关键辅助文字 **至少 12 px** 为初始尺寸，避免主要操作或解释落在当前 8–10 px 区间；装饰性标签无需统一放大。提高弱提示文字的辨识度，统一输入、消息卡、状态提示的间距、边框和圆角，控制装饰阴影，不添加新字体资源或 UI 依赖。

状态不能只靠颜色区分。为发送、停止、引用、下载和证据展开保留清晰的键盘焦点；长任务 ID、JSON 和长错误允许换行或在局部滚动，不删减这些信息来解决溢出。初始验收覆盖 1440 px 桌面、390 px 与 320 px 窄屏，确认输入区、按钮、活动提示和模型切换可访问。

具体色值、间距和动画节奏是实施时可微调的细节，不属于新的产品决策。样式回归截图用于检查网页，不检验模型外观，也不进入 Agent 视觉评测案例集。

### 6. 验证使用受控延迟与真实页面，不新增付费链路

| 验证层 | 验证内容与方式 | 通过依据 |
| --- | --- | --- |
| 状态单测 | 表驱动输入首次接受、澄清后处理、待答、两级排队、生成／减面、文件准备、纠偏、终态、旧事件、未知阶段 | 输出与已知事实匹配；不修改发送资格或业务状态 |
| 连接单测 | fake socket、延迟 HTTP 与可注入时间；相同游标心跳、静默 15 秒、onopen 无快照、旧 socket、切换和前台恢复 | 提示及时失效和恢复；每代只有一条恢复链；无制作请求 |
| 浏览器契约 | 扩展 `workspace.browser.mjs` 的 HTTP/WS 夹具，明确控制发送延迟、Agent 静默、阶段推进和乱序响应 | 提交到处理反馈连续；一个活动节点；终态无残留；草稿、焦点、滚动和引用保持 |
| 本机集成 | 复用 `TestConversationBrowserHarness` 与 `workspace.go-browser.mjs`；脚本继续拒绝非本机、非 controlled 服务 | 真实 Go 快照驱动页面；刷新、仅回答、停止、重连与版本流程不回归 |
| 样式检查 | 在三个视口检查长内容、键盘焦点、减少动态效果与截图 | 无页面整体横向溢出、按钮未被遮挡，诊断与导出仍可用 |
| 基础检查 | Node 测试、静态资源构建、Go 全量受控测试及 server 构建 | JS 页面实际可加载，Go 嵌入资源完整；没有真实模型调用 |

`npm run build` 当前仅准备模型查看器依赖，不会独立证明应用 JS 的状态逻辑正确；必须结合 Node 和浏览器验证。现有 Go 全量测试、浏览器测试与本次新增断言分别记录范围，不启动真实 DeepSeek／Tripo 或完整 Agent 案例集。浏览器中的合成模型和可控进度不能记为真实供应商验收。

## Risks / Trade-offs

- 已有公开字段不够区分所有微小阶段 → 统一显示“正在处理”或“正在准备模型文件”，不凭时间和模型文字猜测，也不在本轮扩展后端接口。
- 旧事件或失败候选影响最新目标 → 按会话／Run／Operation／序号筛选，终态和停止覆盖动画，补充同 Run 纠偏和跨 Run 迟到事件测试。
- 无事件进展被误认为断线 → 用有效快照接收时间而不是事件游标续期；页面过期只触发只读同步，不修改业务状态。
- 新计时器泄露、重复重连或后台节流 → 沿用连接代次并增加 socket 身份校验，统一清理；前台恢复重新检查；使用假时间复现。
- 增大字号导致长技术内容溢出 → 长内容换行或局部滚动，在窄屏验收；保持所有技术信息及功能入口。
- 动画重绘干扰历史阅读或辅助技术 → 独立节点、状态去重、减少动态效果、焦点及滚动回归；不逐次心跳播报。

## Migration Plan

1. 在独立变更内完成前端模块、页面和样式调整，运行上述受控验证，生成本次验证记录。
2. 将静态文件随 Go 程序重新构建。只修改磁盘上的 HTML／JS 而不重建已运行二进制不会更新线上嵌入页面；发布时必须按既有程序发布方式更换版本。
3. 本轮不执行线上发布。后续获得发布指令时保留当前配置、SQLite、模型文件和会话，不执行国内站切换时的一次性数据清理。
4. 无数据库或接口迁移；浏览器刷新即可加载新页面。回退到本变更前的兼容程序／静态资源版本即可恢复旧展示，仍保留当前数据和 Tripo 国内配置。

此方案没有需要在实施前补问的产品范围问题。2026-09-19 已完成实施和受控验收，详见 tasks.md 与 docs/verification/chat-feedback-and-polish.md。
