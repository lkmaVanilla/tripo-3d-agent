## Why

当前澄清和生产准备先保存业务状态，再由 Eino 保存检查点，最后单独设置 `CheckpointReady`；进程在这些写入之间退出，会留下不能回答的等待状态，或让新的等待状态使用旧检查点恢复。回答在恢复时被立即清空，又使同一检查点的重放可能丢失已接受的答案；这些问题影响已经承诺的静态道具 MVP 恢复能力，需要在现有范围内修复。

## What Changes

- 建立带身份和递增代次的暂停记录，区分待提交暂停与已提交恢复点；不再以 `CheckpointReady` 布尔值判断能否恢复。
- 在一个 SQLite 事务中提交 Eino 检查点、对应的业务暂停状态、恢复元数据及事件；恢复前核对会话、暂停身份、代次和检查点完整性。
- 为检查点尚未生成的待提交暂停保留有限的重建信息，重启后重放已接受的工具提议来建立检查点，不重新请求模型决定已确定的动作。
- 按等待 ID 保留已经接受的用户答案；生产恢复继续使用原操作 ID、任务 ID 和已经保存的结果。重放不得重复增加澄清次数、生产次数、队列条目或产物记录。
- 在正常调度之前核对恢复状态，覆盖首次暂停、后续暂停、答案交付、排队、停止及到期之间的竞态，并为无法安全恢复的记录提供明确的失败原因。
- 提供旧记录的兼容与迁移路径；保留已知任务续查、未知提交不重发、预算和截止时间不重置的既定规则。
- 增加真实 Eino Runner 配合受控模型/Provider 的故障注入及进程重启回归测试，区分协议验证与真实供应商调用。

范围限定为检查点一致性修复。非目标：图片、绑骨、动画、Session/Run/Asset 领域重构、ContextBuilder、通用工具框架、WebSocket 推送性能优化、模型/框架升级、分布式调度，以及完整 Agent 案例集评测。

本提案细化而不放宽 [CONTEXT.md](../../../../CONTEXT.md) 的恢复约束，以及 [ADR 0009](../../../../docs/adr/0009-recover-known-executions-without-resubmission.md)、[ADR 0010](../../../../docs/adr/0010-sqlite-and-local-artifacts.md)、[ADR 0013](../../../../docs/adr/0013-execution-limits-and-local-stop.md)、[ADR 0016](../../../../docs/adr/0016-bounded-production-concurrency-and-queue.md) 的要求。无法证明可恢复的旧损坏记录不会被猜测修复；具体兼容规则在设计与场景规格中明确。

## Capabilities

### New Capabilities

- `checkpoint-recovery`: 暂停原子提交、恢复点身份校验、待提交暂停重建、已接受答案与操作结果的安全重放、启动对账及恢复故障验证。

### Modified Capabilities

无。提案形成时，`openspec/specs/` 尚无已归档能力；`first-asset-demo` 的 `asset-demo` 规格仍位于变更目录。本变更新增专门的恢复行为规格，细化该演示已有的恢复承诺，不改写或归档前一变更，不修改既定产品边界。

## Impact

- 主要实现范围：`internal/app/agent.go`、`service.go`、`store.go`、`types.go`；允许新增小型恢复协调文件，保持单 Go 服务与当前 Eino ADK。
- 存储：为会话和检查点增加恢复元数据、待提交暂停和答案记录；采用兼容读取与可重复执行的增量迁移，保留原数据库与模型文件。
- 接口：保持现有会话、回答、停止、队列重试 HTTP 请求结构；等待状态只在可恢复时对外生效，恢复失败沿用现有失败状态及解释。新增恢复事件使用已有脱敏导出与 WebSocket 通道。
- 验证：新增恢复专项测试，并保留现有澄清、已知任务恢复、预算、匿名隔离、队列及 DeepSeek 协议回归。计划不要求真实付费 API 调用，也不把系统回归通过计作 Agent 评测完成。
- 提案阶段仅生成规划文档；业务实现、迁移逻辑及恢复专项验证已在后续 apply 阶段完成，未迁移当前开发数据目录。本变更于 2026-09-13 同步主规格并归档，最终实现与验证边界见 [design.md](design.md) 的 Implementation Notes。
