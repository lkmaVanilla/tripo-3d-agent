## Why

当前应用把一次资产请求与整个会话绑定：首次生成结束后不能继续发送制作目标，候选模型虽已留存，却没有可靠的版本引用和来源关系。面向 3D 创作者的下一阶段需要把已确认的同资产持续创作方向落成聊天工作台，使用户可以在原会话引用历史模型继续加工，同时保留每次执行的预算、恢复和可信结果边界。

## What Changes

- 建立聊天首页与资产工作台：首次消息创建会话并进入工作台，持续对话、制作卡片、模型预览和本会话版本列表共同呈现过程与结果。
- **BREAKING（交互语义）**：会话与单次执行分离。一次目标完成、失败或被用户停止后，会话可以接受新消息；后续执行使用新的预算和检查点，已结束执行不复活。澄清和本次目标内的纠偏仍属于原执行。
- 同一会话同时最多一个活动执行。用户已确认执行期间仅保留草稿，完成或停止后才能发送下一条要求；等待澄清时仍可回答当前问题，不引入目标排队或运行中指令合并。
- 加入会话内模型版本：旧模型不覆盖，实际输出追加版本，记录生产执行、操作、真实输入版本和技术证据；允许从本会话任意可处理历史版本继续制作。
- 聊天显式携带版本引用，预览焦点与生产输入分开。即使属于同一匿名访客，也不能引用其他会话的模型；版本归属、选择、保存及去重由 Go 后端保证。
- 新执行可承接用途、约束和所选版本事实，并区分生成、减面、解释已有结果与不支持能力的回答。纯回答不产生模型版本，不被伪装为新资产交付。
- 继续使用已接入的文本生成、减面和技术检查；补齐将本应用既有 GLB 提供给 Tripo 后续加工的内部文件上传适配，解决旧供应商下载地址失效问题。这不开放用户导入模型。
- 保留旧执行的提示、工具协议、恢复字节、结果和额度；增量建立会话与版本索引。新页面和兼容接口共享按执行核验的事实，不把完整模型 History 或原始提议当作聊天中的已验证结论。
- 采用用户已确认的会话整体保留策略：会话无在途执行时，自最后一次执行结束保留 7 天；到期前正式继续使用后按后续执行结束时间续期，查看、下载、心跳和草稿不续期，活动执行期间不删除历史版本。迁移既有记录不续期，具体规则见 design 的 D8。

### Scope and Non-goals

已确认范围：标准聊天入口、同会话持续创作、只引用本会话生产的模型、保留历史版本、单活动执行、忙碌时保留草稿及最后一次执行结束后保留 7 天的整体续期策略。版本来源关系和后端职责沿用本轮探索建议。

本次不接入图片生成/图片到模型、外部模型导入、绑定、动画、跨会话资产库、资产分享或协作；不做多个独立资产的混合编辑、无限画布、几何差异合并、动态 Skill、跨会话记忆或多 Agent。停止仍表示停止本次本地执行；暂停后恢复和停止后的远端结果取回另行规划，不能通过新执行隐式重提旧任务。逐 token 输出和更换前端框架不是本次验收条件。

## Capabilities

### New Capabilities

- `continuous-asset-conversation`: 会话与执行分离、单活动执行、消息幂等、澄清归属、上下文承接、预算及保留生命周期。
- `session-asset-versions`: 会话内不可变模型版本、真实来源、显式引用、历史证据、可处理性及供应商输入准备。
- `chat-asset-workspace`: 首页到工作台、可展示聊天消息、制作卡片、版本预览引用、HTTP 命令与 WebSocket 恢复。

### Modified Capabilities

- `agent-audience`: 新执行开放同会话后续目标，按执行冻结提示/Skill/工具协议，继续限定当前真实制作能力。
- `verified-results`: 正式结果按执行核验，区分回答与交付，解除旧变更中的网页保持不变限制，保持历史事实与多入口一致。
- `checkpoint-recovery`: 明确恢复身份属于一次执行，隔离同会话的不同执行、答案和副作用，扩充会话/版本登记的崩溃恢复及旧记录兼容。

## Impact

- 主要影响 `internal/app/` 的执行生命周期、存储、上下文、工具门禁、结果及 API；`internal/tripo/` 的内部文件上传；`internal/web/static/` 的页面组织与状态呈现。沿用 Go、Eino ADK、DeepSeek、Tripo、SQLite、Go embed 和 model-viewer，无新增外部基础服务。
- 新会话 API 与聊天投影并行于旧单执行接口。旧会话 URL、已有下载和执行导出保持可解析；迁移和访问控制覆盖历史文件，不能按首个执行的到期时间删除仍被有效会话引用的模型。
- 现有 `agent-audience` 明确排除交付后追加目标，`verified-results` 要求网页不变，本提案以显式 delta 修改。恢复与可信结果已有保证继续适用于每次执行，不能因拆分实体被削弱。
- [PROJECT_BRIEF.md](../../../../PROJECT_BRIEF.md)、[CONTEXT.md](../../../../CONTEXT.md) 和 [ADR 0021](../../../../docs/adr/0021-continuous-asset-collaboration.md) 的长期方向是本次依据；实施时更新阶段状态、补充执行/版本及保留期决策。历史 ADR 0011、0013、0014、0018 通过新决策说明适用范围，不重写过去事实。
- `first-asset-demo` 仍是独立的旧 MVP 变更，本轮不修改或归档它；其“一会话一请求”假设由本阶段新规格取代，后续归档不得把旧限制重新同步为现行要求。
- 验收包含同会话三次制作与历史版本引用、消息并发/幂等、强制退出恢复、旧 v1/v2 升级、跨会话拒绝、可信结果和保留期竞争。真实 Tripo 链路、固定 Provider 的真实 Agent 评测、系统回归分别报告，不把本方案或局部样本当作既定 20 案例 × 3 次正式评测通过。
