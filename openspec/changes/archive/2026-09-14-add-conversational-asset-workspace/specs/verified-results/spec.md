## RENAMED Requirements

- FROM: `### Requirement: 输出接口共享正式结果并保持网页不变`
- TO: `### Requirement: 输出接口共享按执行核验的正式结果`

## MODIFIED Requirements

### Requirement: 正式结果以实测证据为依据

系统 MUST 根据本次执行的已保存状态、交付资产引用和技术报告生成正式结果，不以整个会话的最新模型代替本次执行的证据。面数、体积、检查项及上限 SHALL 来自实际报告，不得用生成参数、模型自由文字或供应商成功状态替代；正式结果 MUST 不宣称未执行的绑定、动画或未检查的类别、风格与外观符合性。输入版本的历史检查与本次目标的检查 SHALL 分别表达，后续目标不得改写旧执行报告、正式结果或其原验收上限。

#### Scenario: 正确引用附带错误解释
- **WHEN** 模型引用技术通过的本次执行资产，报告为 2,645 个三角面，但模型解释声称只有 1,000 面且绑定、动画已经完成
- **THEN** 正式结果采用 2,645 面和真实检查范围，不包含这些虚构事实，原始错误提议仍可在脱敏执行记录中追踪

#### Scenario: 无法获取可信面数
- **WHEN** 已下载文件无法解析或不在技术检查支持范围内
- **THEN** 正式结果指出文件检查失败及面数无法验证，不把缺省零值当作实测面数，也不据此宣告面数达标

#### Scenario: 新目标采用不同技术上限
- **WHEN** 原版本按 5,000 个三角面上限通过检查，用户在后续执行中要求减到 3,000 个三角面
- **THEN** 原版本保留原实测报告和 5,000 面验收事实，新执行独立保存其 3,000 面目标与检查，不把原版本在新目标下的差距解释为旧检查失败

### Requirement: Agent 决策与事实核验分离

Agent SHALL 保留交付或结束本次执行的选择与原始说明。Runtime MUST 校验新资产交付引用属于当前执行的真实输出且通过该执行既定技术检查，不能因输入版本属于同一会话就把它当作当前执行的新交付。Agent 选择结束仅能证明其作出结束决定，原始说明不得自动成为系统已核验的停止原因。

#### Scenario: 无效交付引用
- **WHEN** Agent 提议交付不存在、属于其他执行或未通过检查的资产
- **THEN** 系统拒绝新资产交付，不设置交付成功终态或该交付引用，并保留提议与拦截证据供评测

#### Scenario: 尚有额度但 Agent 结束
- **WHEN** Agent 选择结束，原始解释声称预算耗尽或所有方案都不可行，但持久化证据不能证明这些说法
- **THEN** 系统可以接受其结束选择，正式结果只说明 Agent 结束了本次执行、是否交付及可核验的现有结果和额度，不认证这些停止理由，也不额外调用模型判定说明真伪

#### Scenario: 结束说明声称成功
- **WHEN** Agent 选择不交付，却在原始说明中宣称已经成功完成全部制作
- **THEN** 正式结果保持未交付，不因该文字改变执行状态或选中交付资产

#### Scenario: 输入版本已满足新要求
- **WHEN** 指定输入版本的可核验技术数据已经满足用户本次要求，且未发生新生产
- **THEN** Agent 可以回答已有版本满足哪些可核验条件，系统将本次标记为回答并引用原版本，不增加版本、不宣称完成新的制作或新资产交付

### Requirement: 结果与终态一致提交

系统 MUST 将单次执行的新终态、正式结果依据、交付引用与相应结束记录作为一致的持久化结果保存，并确保会话不会把已结束执行持续呈现为活动执行或在结束事实未提交时接受并行目标。最新停止和期限判断优先，重复收尾或迟到回调不得覆盖既有终态、正式结果或其他执行的状态；正式事实生成不得增加模型调用或生产副作用。

#### Scenario: 停止后成功回调到达
- **WHEN** 用户停止当前执行已经生效，较早启动的生产或 Agent 成功结果随后到达
- **THEN** 该执行仍保持停止，正式结果不变为交付；已有产物按原规则保留，预算和期限不被重置，会话中的后续执行不受该回调影响

#### Scenario: 收尾写入失败或重复执行
- **WHEN** 收尾持久化失败，或者进程退出后同一收尾逻辑再次被执行
- **THEN** 系统不发布与持久化状态矛盾的成功结论；重试或恢复不重复产生终态业务效果，也不新增生产，已提交结束可以被可靠识别并恢复会话后续交互

#### Scenario: 会话随后产生其他版本
- **WHEN** 旧执行的正式结果已经保存，而同会话新执行产生了另一个模型版本
- **THEN** 读取旧执行时仍获得它原来的结果、交付版本和报告，不因会话当前预览、最新版本或活动执行改变旧结论

### Requirement: 输出接口共享按执行核验的正式结果

系统 SHALL 向会话聊天投影、单执行兼容接口、WebSocket 与 JSON 导出提供按执行身份一致的正式结果，保留旧接口的字符串结果及兼容状态字段。页面 SHALL 按聊天资产工作台规格组织消息、制作卡片和版本预览，不再受旧页面固定文案、布局及交互保持不变的限制。原始模型说明和外部错误正文 SHALL 保留为有来源的脱敏证据，不混入程序核验的事实正文，也不把完整模型内部历史直接当作用户聊天记录。

#### Scenario: 多个入口读取同一终态
- **WHEN** 有权限的访客通过会话聊天、单执行接口、WebSocket 重连或执行记录导出读取同一执行
- **THEN** 各入口的正式结论、交付引用和技术数据一致，原始提议仍作为独立证据存在，后续执行的结果不会替换被读取执行的结果

#### Scenario: 当前页面继续使用
- **WHEN** 兼容客户端按旧接口读取原单执行请求，或用户打开它对应的新工作台
- **THEN** 旧接口仍返回可使用的结果字符串与原执行语义，新工作台可以采用聊天布局展示同一执行的状态、报告和记录，不需要伪造成功、改写历史证据或保留旧固定文案

## ADDED Requirements

### Requirement: 回答结局不冒充资产交付

系统 SHALL 区分只回答的执行结局与真实资产交付。解释已有结果、不支持能力说明及无需新增生产的回答 SHALL 使用独立的回答结局；只回答时生产提交数和新版本数 MUST 为零，实际模型调用仍按该执行计数。回答文本 SHALL 标明 Agent 来源；其中可核验的资产事实引用真实版本证据，无法核验的外观或因果说明不得被提升为程序认证的事实。发生过生产的执行 MUST 按其真实生产与结果证据收尾，不得借回答结局隐藏已提交任务。

#### Scenario: 询问历史版本的检查结果
- **WHEN** 用户指定本会话版本并询问其面数、体积或技术检查范围
- **THEN** Agent 的说明引用该版本的实际证据，本次执行记录实际模型调用和回答结局，不调用生产、不新增版本，也不重写原版本的交付结论

#### Scenario: 询问当前未接入能力
- **WHEN** 用户询问能否为指定模型绑定或制作动画
- **THEN** 系统以回答说明当前能力限制，不产生 Tripo 制作任务或新版本，不把限制说明标记为资产交付成功
