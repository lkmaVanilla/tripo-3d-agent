## Context

见 proposal.md 的动机与范围。当前没有业务代码；已有 Go module、需求共识与十八份 ADR。实现遵守 ADR 0004、0008、0009、0010、0011 的职责、存储与恢复边界。

## Goals / Non-Goals

**Goals:** 提供单进程可启动的浏览器演示，所有外部副作用经过持久化操作记录和额度校验；真实服务与测试替身共享类型化接口。

**Non-Goals:** 不构建动态工具平台，不引入独立任务服务，不用模拟响应冒充真实演示，不把首条链路测试等同于完整案例集验收。

## Decisions

1. 使用 Go 标准 HTTP 服务、Eino ChatModelAgent/Runner 和 DeepSeek 适配器。工具包含澄清、准备生产、生成、减面、交付或停止；模型决定动作，Go 工具完成轮询、下载与检查。避免让模型逐次查询异步状态。
2. SQLite 保存会话快照、操作、检查点与追加事件。每个请求由一个执行器推进，数据库事务负责预算和操作记录的一致性；模型调用包装器独立计数。使用请求级取消和绝对截止时间，浏览器连接不拥有后台任务生命周期。
3. 澄清和生产排队通过 Eino 中断保存检查点；恢复沿用同一请求。提交前记录操作，收到 task ID 立即持久化。重启后已知任务继续查询，未知提交终止。模型历史中的工具关联与 reasoning_content 必须保留。
4. 三份项目运行时 Skill 作为随二进制嵌入的只读资源，按需加载到同一个 Agent。它们与 .agents/ 中供开发助手使用的 OpenSpec 技能分开。
5. GLB 检查先限制下载体积与资源引用，再解析文件并校验网格和索引；仅支持静态、自包含、非压缩三角面网格。面数基于全部网格的实际索引或顶点数量，禁止将请求 face_limit 当成实测值。
6. 前端采用静态页面和最小 3D viewer，后端提供相同匿名鉴权的模型地址。WebSocket 发送持久化事件和状态，重连依赖事件序号。生产参数固定 Tripo 模型 v3.1-20260211、三角面和常规贴图，Agent 仅可调整已授权字段。
7. 配置从环境和被忽略的 .env 加载，密钥不写入日志或导出。测试通过本地 HTTP 服务模拟供应商协议和有限工具反馈，真实验收必须另行调用实际供应商。

## Risks / Trade-offs

- 外部提交与 SQLite 不能原子提交 → 先扣减并写操作记录，未知结果停止，不盲目重试。
- Eino 或供应商协议可能变化 → 锁定依赖，并验证工具历史、中断恢复和实际响应结构。
- 提交次数不能保证金额上限 → 展示消耗次数，沿用已接受的次数预算，真实演示保留供应商返回的用量证据。
- 缺少凭证 → 完成本地验证与明确配置说明，真实演示任务保持未完成。

## Migration Plan

这是首次业务实现，无旧数据迁移。启动时创建数据目录和表；运行前配置凭证并执行检查。数据目录保持持久化，重新部署沿用原数据库与模型文件。
