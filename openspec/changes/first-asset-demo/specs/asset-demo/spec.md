## Purpose

让独立游戏开发者在浏览器中描述一个静态道具，经过必要澄清后获得真实生产的候选模型、实测技术报告和可追踪的 Agent 决策过程。演示将接口成功、产物合格与 Agent 行为评测区分展示。

## ADDED Requirements

### Requirement: 匿名会话隔离
系统 SHALL 自动签发匿名凭证，允许同一访客建立多个会话；一个会话只承载一个资产请求。列表、对话、进度、模型下载、导出与停止操作 MUST 校验归属。

#### Scenario: 多访客访问
- **WHEN** 另一个匿名访客获得某会话 ID
- **THEN** 系统拒绝读取或操作该会话及其模型、进度和记录

### Requirement: 意图澄清与计划
Agent SHALL 从自然语言提取静态道具意图和硬约束，展示计划及默认假设；关键需求明确或最多三轮澄清后继续执行，无法解决的硬约束冲突必须解释并结束。

#### Scenario: 木箱请求
- **WHEN** 用户提交“给我的俯视角游戏原型做一个低模木箱”
- **THEN** 页面展示意图、必要澄清、GLB 交付计划，以及未指定时采用的 5,000 三角面和 10 MiB 默认上限

### Requirement: 真实生产与技术反馈
系统 SHALL 调用真实 Tripo 生成静态道具、跟踪任务、下载 GLB，并依据实际文件检查有效性、总三角面数和文件体积。Agent SHALL 根据检查失败项选择减面、保留约束重新生成或停止；检查通过不构成视觉符合性结论。

#### Scenario: 首次通过
- **WHEN** 第一次产物通过全部技术检查
- **THEN** 交付该产物，不人为追加生产操作

#### Scenario: 面数超限
- **WHEN** 文件有效但实测面数超过验收上限且还有纠偏额度
- **THEN** Agent 根据工具条件选择纠偏或停止，纠偏后重新执行全部技术检查，原验收上限不变

### Requirement: 强制执行边界
系统 MUST 持久化并强制执行 CONTEXT.md 规定的澄清轮次、生产次数、模型调用额度、30 分钟生产期限、并发名额及队列上限。失败提交和未知提交消耗生产额度，未知提交不能自动重发。

#### Scenario: 额度用尽
- **WHEN** 生产提交已达到三次或模型调用达到二十次
- **THEN** 系统禁止新增生产，仍在期限内完成已提交任务的确定性查询和检查，并保留违规提议作为评测证据

#### Scenario: 排队与停止
- **WHEN** 生产名额已满
- **THEN** 请求按持久化顺序排队，不启动生产计时；队列满时提示繁忙并保留需求，停止排队后不再自动启动

### Requirement: 恢复与到期
系统 SHALL 在断线时继续后台执行，在重启时恢复待澄清检查点、等待队列及已知 Tripo 任务；预算和截止时间不重置。已终止、到期或提交结果未知的请求 MUST 遵守既定停止规则，并按 CONTEXT.md 的保留期限清理。

#### Scenario: 已知任务恢复
- **WHEN** 服务重启前已保存 Tripo 任务 ID，且请求未终止或超时
- **THEN** 继续查询原任务，不重复提交首次生成

### Requirement: 结果与执行证据
系统 SHALL 提供 WebSocket 进度、可旋转的 GLB 预览、下载、技术检查报告、执行事件详情和脱敏 JSON 导出。Agent 提议、Runtime 放行或拦截、真实工具结果 MUST 分别关联记录。

#### Scenario: 页面重连
- **WHEN** 用户刷新或 WebSocket 重新连接
- **THEN** 从持久记录恢复完整时间线和当前状态，避免把计划显示为已执行事实

### Requirement: 单次执行评测
系统 SHALL 根据执行记录核验预算遵守、验收结论和解释证据，并将该结果与产物报告分别展示。固定响应测试、真实链路证据与 20 案例各 3 次的 Agent 验收报告 MUST 明确区分。

#### Scenario: 缺少真实凭证
- **WHEN** 未配置外部服务凭证
- **THEN** 页面提示配置缺失，不把模拟模型或测试运行展示为真实生成成功
