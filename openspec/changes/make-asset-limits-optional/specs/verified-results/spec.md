## MODIFIED Requirements

### Requirement: 正式结果以实测证据为依据

系统 MUST 根据本次执行的已保存状态、交付资产引用和技术报告生成正式结果，不以整个会话的最新模型代替本次执行的证据。面数、体积、检查项及上限 SHALL 来自实际报告，不得用生成参数、模型自由文字或供应商成功状态替代；正式结果 MUST 不宣称未执行的绑定、动画或未检查的类别、风格与外观符合性。新版报告 SHALL 分别表达实测值与可选验收上限：有可信测量但无上限时对应比较标为不适用，无法取得可信测量时标为无法验证，不以缺省零值或生产目标充当测量与上限。输入版本的历史检查与本次目标的检查 SHALL 分别表达，后续目标不得改写旧执行报告、正式结果或其原验收上限。

#### Scenario: 正确引用附带错误解释
- **WHEN** 模型引用技术通过的本次执行资产，报告为 2,645 个三角面，但模型解释声称只有 1,000 面且绑定、动画已经完成
- **THEN** 正式结果采用 2,645 面和真实检查范围，不包含这些虚构事实，原始错误提议仍可在脱敏执行记录中追踪

#### Scenario: 无法获取可信面数
- **WHEN** 已下载文件无法解析或不在技术检查支持范围内
- **THEN** 正式结果指出文件检查失败及面数无法验证，不把缺省零值当作实测面数，也不据此宣告面数达标

#### Scenario: 新目标采用不同技术上限
- **WHEN** 原版本按 5,000 个三角面上限通过检查，用户在后续执行中要求减到 3,000 个三角面
- **THEN** 原版本保留原实测报告和 5,000 面验收事实，新执行独立保存其 3,000 面目标与检查，不把原版本在新目标下的差距解释为旧检查失败

#### Scenario: 无上限产物超过旧默认值
- **WHEN** 本次无面数和体积上限，合法文件实测为 6000 个三角面和 12 MiB
- **THEN** 报告展示真实测量、两个空上限与不适用比较，文件检查通过后可技术通过，不因旧默认值触发纠偏，不声称低于用户上限

#### Scenario: 单项上限独立验收
- **WHEN** 用户只设 3000 面上限，产物有效且实测 3500 面、12 MiB
- **THEN** 面数比较失败，体积比较不适用且显示实测值，整体技术不通过；不得把体积判为超过 10 MiB

#### Scenario: 无约束但文件无效
- **WHEN** 两项上限未设置而返回的文件损坏或不在支持范围
- **THEN** 文件不能通过检查，面数不可验证，系统不因无上限放行交付；取得完整字节时体积测量仍可记录

#### Scenario: 报告上限被伪造为空
- **WHEN** 意图有明确面数上限，但候选报告将该值省略或标为不适用
- **THEN** 系统一致性校验拒绝该报告，不把缺失字段当成解除限制，不通过正式结果认证

### Requirement: Agent 决策与事实核验分离

Agent SHALL 保留交付或结束本次执行的选择与原始说明。Runtime MUST 校验新资产交付引用属于当前执行的真实输出且通过该执行既定技术检查及可核验的加工目标判断，不能因输入版本属于同一会话就把它当作当前执行的新交付。Agent 选择结束仅能证明其作出结束决定，原始说明不得自动成为系统已核验的停止原因。

#### Scenario: 无效交付引用
- **WHEN** Agent 提议交付不存在、属于其他执行或未通过检查的资产
- **THEN** 系统拒绝新资产交付，不设置交付成功终态或该交付引用，并保留提议与拦截证据供评测

#### Scenario: 尚有额度但 Agent 结束
- **WHEN** Agent 选择结束，原始解释声称预算耗尽或所有方案都不可行，但持久化证据不能证明这些说法
- **THEN** 系统可以接受其结束选择，正式结果只说明 Agent 结束了本次执行、是否交付及可核验的现有结果和额度，不认证这些停止理由，也不额外调用模型判定说明真伪

#### Scenario: 结束说明声称成功
- **WHEN** Agent 选择不交付，却在原始说明中宣称已经成功完成全部制作
- **THEN** 正式结果保持未交付，不因该文字改变执行状态或选中交付资产

#### Scenario: 输入版本已满足新要求
- **WHEN** 指定输入版本的可核验技术数据已经满足用户本次要求，用户未要求进一步降低面数或明确重新生成，且未发生新生产
- **THEN** Agent 可以回答已有版本满足哪些可核验条件，系统将本次标记为回答并引用原版本，不增加版本、不宣称完成新的制作或新资产交付

#### Scenario: 技术通过不掩盖减面目标未完成
- **WHEN** 无绝对面数上限的进一步减面执行产生了有效文件，但没有实际降低初始输入的面数
- **THEN** Runtime 不接受成功交付，正式结果区分文件技术通过与减面目标未完成，保留候选和实际报告

### Requirement: 输出接口共享按执行核验的正式结果

系统 SHALL 向会话聊天投影、单执行兼容接口、WebSocket 与 JSON 导出提供按执行身份一致的正式结果，保留旧接口的字符串结果及兼容状态字段。页面 SHALL 按聊天资产工作台规格组织消息、制作卡片和版本预览，不再受旧页面固定文案、布局及交互保持不变的限制。原始模型说明和外部错误正文 SHALL 保留为有来源的脱敏证据，不混入程序核验的事实正文，也不把完整模型内部历史直接当作用户聊天记录。

#### Scenario: 多个入口读取同一终态
- **WHEN** 有权限的访客通过会话聊天、单执行接口、WebSocket 重连或执行记录导出读取同一执行
- **THEN** 各入口的正式结论、交付引用和技术数据一致，原始提议仍作为独立证据存在，后续执行的结果不会替换被读取执行的结果

#### Scenario: 当前页面继续使用
- **WHEN** 兼容客户端按旧接口读取原单执行请求，或用户打开它对应的新工作台
- **THEN** 旧接口仍返回可使用的结果字符串与原执行语义，新工作台可以采用聊天布局展示同一执行的状态、报告和记录，不需要伪造成功、改写历史证据或保留旧固定文案

#### Scenario: 未设置上限在各入口一致展示
- **WHEN** 读取新版无上限执行的计划、需求差异、结果、版本报告、WS 补读及 JSON 导出
- **THEN** 各入口一致表达上限未设置及比较不适用，保留实际测量，不显示为零上限、旧默认或达标；历史缺失证据仍表达未知
