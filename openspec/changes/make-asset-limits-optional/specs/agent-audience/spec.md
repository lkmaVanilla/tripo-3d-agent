## MODIFIED Requirements

### Requirement: 受众扩大不扩大当前生产权限

Agent SHALL 将文本到单个静态、自包含 GLB、有限减面与重新生成表达为当前阶段能力，并允许用户在同一会话中基于该会话的历史模型版本提出后续制作目标。每次新目标 SHALL 建立独立执行；本次目标内的澄清和纠偏继续使用原执行的预算与限制。Agent MUST 继续遵守 Tripo-only、技术检查、预算及澄清规则，不将供应商潜在能力或长期方向宣告为当前已接入能力，也不得悄悄将不支持的要求改成一个不同的静态资产目标。

#### Scenario: 要求尚未接入的能力
- **WHEN** 用户要求图片输入、外部模型导入、绑定、动画或引用其他会话的模型
- **THEN** Agent 在说明或必要澄清中指出当前版本的限制，不宣称已执行相应操作，不调用其他生产工具补齐能力，也不未经明确需求变更就以静态生成替代

#### Scenario: 普通静态请求沿用原规则
- **WHEN** 创作者提出当前支持的文本静态资产需求
- **THEN** Agent 对新版执行按用户要求及适用历史来源保存可选技术上限，不补强制默认，继续遵守至多三轮澄清、生产预算及技术纠偏规则，生产与技术通过仍由既定执行和检查证据决定

#### Scenario: 在原会话引用历史模型继续制作
- **WHEN** 本会话当前执行已经结束，用户明确引用该会话已有模型版本并要求减面
- **THEN** 新执行按本次目标和指定版本理解需求、选择已接入工具，保留旧执行的预算、报告和结果，不把后续制作误判为未支持能力，也不复活旧执行

#### Scenario: 内部文件准备不开放模型导入
- **WHEN** 工具为加工本会话已有模型而向 Tripo 准备本应用保存的文件
- **THEN** Agent 只把该动作作为已有版本的内部输入准备，不宣称用户可以上传外部模型、引用其他会话或使用新增建模能力

### Requirement: 提示升级保留在途会话的执行版本

系统 MUST 按单次执行记录并冻结实际使用的提示、任务指引和工具协议版本，让在途旧执行继续使用与其既有恢复依据一致的受支持版本。新会话创建入口及会话消息入口中新接受的目标 SHALL 使用本阶段 v4 执行版本；旧单请求创建入口 SHALL 作为明确的兼容例外，继续创建使用 v2 的单次执行并返回原单请求结果语义。兼容执行所在会话随后通过新消息入口接受的目标 SHALL 使用独立的 v4 执行，不升级或复活原执行。已开始的旧执行不随会话界面升级切换版本。版本更新 MUST 保留旧执行的上下文输入协议、已接受提议、问题、答案、操作和检查点，不重置预算或期限；未知、矛盾或损坏的恢复依据仍按现行恢复规则处理。

#### Scenario: 新会话使用新受众定义
- **WHEN** 更新后的服务通过新会话入口创建会话及其首次执行
- **THEN** 该执行使用更新后的受众与能力指引，执行记录标明实际提示版本与所加载 Skill 的内容版本

#### Scenario: 旧暂停在升级后恢复
- **WHEN** 更新前的执行处于待澄清、排队、待提交暂停或已知生产任务状态，且原恢复依据完整可验证
- **THEN** 系统使用该执行的原提示、任务指引、工具及上下文输入协议恢复原问题、答案或操作，纯重建不新增模型调用，不因界面和能力更新重复提交生产或覆盖已有事实

#### Scenario: 恢复版本不可证明
- **WHEN** 执行版本与其恢复依据矛盾、版本未知或协议完整性校验失败
- **THEN** 系统明确记录恢复不可用，不修改历史版本或跳过完整性检查；已知任务仍按原期限的确定性恢复规则处理，未知提交不自动重发

#### Scenario: 同一会话保留不同执行版本
- **WHEN** 旧版本执行完成后，用户在同一会话正式发送新的制作要求
- **THEN** 新执行采用本阶段版本及独立上下文，旧执行仍保留其原版本和恢复证据，不能把新目标追加进旧执行的检查点或改写旧模型调用记录

#### Scenario: 旧创建入口保留单执行兼容协议
- **WHEN** 兼容客户端通过 `POST /api/sessions` 创建新的单请求执行
- **THEN** 系统创建对应包装会话及 v2 执行，保留该入口的原字段、单请求结果及执行协议；随后经 `POST /api/conversations/{id}/messages` 接受的新目标另建 v4 执行，不把兼容接口悄悄切换为会话最新结果

#### Scenario: 新旧约束协议同会话共存
- **WHEN** 原会话有按旧规则接受的 v3 执行，升级后用户在其结束后发送新目标
- **THEN** 原执行保留原上限、Skill 内容版本、报告和恢复证据，新目标采用 v4 可选约束协议；不把 v4 空值回写到原执行

#### Scenario: 旧入口仍采用兼容默认
- **WHEN** 升级后兼容客户端通过旧单请求入口创建 v2 执行且未指定技术上限
- **THEN** 该兼容执行仍按 v2 规则补全上限并标明执行版本；网页使用的新聊天入口不得借此继续补全默认
