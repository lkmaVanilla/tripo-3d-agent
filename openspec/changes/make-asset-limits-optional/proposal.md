## Why

当前系统将用户未提出的 5,000 个三角面、10 MiB 自动变为硬性验收上限，可能让合法产物被判失败并触发不必要的减面或重新生成。这两个值源于木箱演示，不能作为面向 3D 创作者的所有资产的统一要求；本次将用户验收约束、生产参数和系统资源保护分开。

## What Changes

- 新聊天执行的面数、文件体积上限分别可选；无用户要求且无应继承的约束时保持未设置，不自动补 5,000 / 10 MiB，也不为填满这两个字段而强制追问。
- 明确区分未提供、显式取消、设置正数上限；引用版本时承接适用的历史约束，用户在新目标中可明确取消或修改，当前 Run 接受后的约束保持冻结。
- 生成目标面数仍由 Agent 按用途选择并受当前工具参数范围限制；它不是验收上限。保留下载、解析、预算和并发保护。
- 始终检查文件有效性并采集可验证的实际面数与体积；未设置上限的比较项标为“不适用”，而非“达标”或“未检查文件”。仅适用约束参与上限验收。
- 调整减面目标判断：用户明确要求降低面数时，没有绝对上限不能让输入自动被判为“无需加工”；须验证输出实际少于输入。
- **BREAKING（限新版聊天执行的数据语义）**：意图与报告中的两个上限允许为空，报告支持 `not_applicable`；同步适配正式结果、需求差异、HTTP/WS 投影、导出和前端渲染，不增加设置面板或重做网页。
- 引入新执行协议 v4；旧 v1/v2/v3 执行、提示、Skill、报告及 checkpoint 保留旧语义，旧单请求创建 API 继续 v2 兼容协议。已有会话中新接受的聊天目标使用 v4。
- 更新非视觉评测的预期：无约束产物不因超过旧默认值失败；保留明确约束、预算和结果可信度的验收门槛。

### Scope and Non-goals

仅修改上述约束语义及其端到端依赖。不接入图片、导入、绑定、动画、视觉检查或新供应商；不扩展当前静态自包含 GLB 支持范围；不取消生产预算、资源限制、同会话引用限制或历史不可变性；不修改既有验证证据以宣称新规则已通过。

### Changes to Existing Agreements

本提案明确取代 CONTEXT.md“默认技术上限”及 ADR 0003、0012 中面向新聊天执行的自动补全规则；技术检查范围、Tripo-only（ADR 0020）、单 Agent 和连续创作（ADR 0022）不变。实施时更新当前文档并记录后继 ADR，保留旧决定的历史与兼容范围。`first-asset-demo` 中的历史演示规格及归档记录不在本变更内重写。

## Capabilities

### New Capabilities

- `optional-asset-constraints`: 可选上限的输入、来源、继承与取消；生产参数和资源限制分离；无绝对上限的减面目标判定。

### Modified Capabilities

- `agent-audience`: 新聊天执行采用可选约束及 v4 指引，保留历史执行与兼容入口。
- `verified-results`: 可选上限的技术报告、正式结果、交付与未适用项的证据语义。
- `continuous-asset-conversation`: 后续目标中约束的显式继承、修改、取消和冻结。

## Impact

- 领域与持久化：`internal/app/types.go`、`conversation_intent.go`、版本来源意图、意图草案与恢复种子；约束必须保留空值与来源，不能以零值或猜测历史数字区分语义。
- Agent 与 Runtime：`agent.go`、`conversation_agent.go`、`profiles.go`、版本化 Skills、`recovery.go`、生产与加工守卫；检查硬编码 v3 分支以免 v4 丢失连续创作保护。
- 检查与结果：`internal/asset/check.go`、`production.go`、`results.go`，统一检查及报告一致性规则，覆盖输入评估、正式交付和确定性恢复。
- 接口与网页：保留既有路由与 WS 协议流程，适配新版数据中未设置的上限、不适用状态和约束变更展示；旧报告保持原事实。
- 验证与文档：Go 回归、网页投影测试、真实 LLM 固定供应商评测、必要的真实 Tripo 冒烟；更新 CONTEXT、README、OpenSpec 背景与相关决策引用。无新增基础设施或运行依赖。
