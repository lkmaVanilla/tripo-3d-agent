# 检查点恢复规格

## Purpose

保证静态道具请求在澄清、排队和生产暂停附近发生进程退出后，能够使用与当前业务事实对应的恢复点继续执行。已经接受的答案、生产操作及其证据不得因恢复而丢失、串用或重复产生副作用；无法证明安全的恢复必须给出明确结果。

## Requirements

### Requirement: 可恢复的暂停发布

Runtime MUST 将一个暂停的恢复点和对外生效的等待状态作为一致的提交结果发布。请求只有在具备匹配、可读取的恢复点时，才能对外进入等待回答或可调度的生产等待状态；待提交暂停不得触发真实生产或被当作已接受的队列条目。

#### Scenario: 首次澄清准备后退出
- **WHEN** 第一个问题及其重建依据已保存，但恢复点提交前进程退出
- **THEN** 重启后系统重建同一个待提交暂停，成功后显示原问题并接受回答，不留下“显示等待但拒绝回答”的状态

#### Scenario: 暂停提交后通知前退出
- **WHEN** 暂停和恢复点已经提交，但页面通知或进程内确认尚未完成时进程退出
- **THEN** 重启后直接识别已经生效的暂停，不依赖额外确认标志、不重复发布逻辑问题或新增队列条目

#### Scenario: 暂停提交失败
- **WHEN** 恢复点与等待状态的共同提交失败
- **THEN** 系统保留提交前的有效恢复点和待提交信息，不发布不完整的新等待状态，也不提交相应生产任务

### Requirement: 恢复点身份一致

Runtime MUST 核对恢复点与其所属会话、逻辑暂停及递增代次的绑定关系和完整性；旧代次、其他会话或内容不匹配的恢复点不得推进当前动作。对同一次提交的重复确认不得重复产生业务效果。

#### Scenario: 第二轮暂停覆盖第一轮
- **WHEN** 第二轮澄清已经生效，旧执行实例尝试使用第一轮的恢复点或提交结果推进请求
- **THEN** 系统拒绝该旧结果，第二轮问题、答案、额度和恢复点保持不变

#### Scenario: 跨会话恢复点混用
- **WHEN** 一个请求被提供另一个会话的恢复点或暂停身份
- **THEN** Runtime 在模型决策或外部副作用之前拒绝恢复，不泄露或修改另一会话的数据

#### Scenario: 提交确认重复到达
- **WHEN** 同一暂停提交的确认被重复处理
- **THEN** 仅存在一次有效暂停、一次相应澄清计数或入队效果，原提交结果可以被识别为已经完成

### Requirement: 待提交暂停重建

Runtime SHALL 使用已持久化、与待提交暂停绑定的模型提议和工具参数重建该暂停；重建 MUST 保留原逻辑暂停身份，不再次调用模型决定同一已确定动作，也不执行实际生产。纯重建不增加模型调用次数；后续真实模型调用仍按既定规则计数。

#### Scenario: 尚无任何检查点
- **WHEN** 存在有效的首个待提交暂停及完整重建依据，但尚无检查点
- **THEN** 系统无需用户重新提交需求即可建立该暂停，并保持已经消耗的模型调用次数

#### Scenario: 新暂停未提交且旧暂停存在
- **WHEN** 请求已准备下一轮澄清或下一次生产暂停，保存新恢复点之前退出
- **THEN** 系统重建该待提交暂停，不把新状态交给旧恢复点继续执行，不重复计算已完成操作

#### Scenario: 重建依据不完整
- **WHEN** 待提交暂停的提议、参数或绑定信息缺失或不一致
- **THEN** 系统明确记录恢复失败，不伪造工具结果、不请求模型猜测原动作，也不自动新增生产

### Requirement: 已接受答案可重放

系统 MUST 将已经接受的用户答案持久绑定到对应的逻辑问题，并在该问题仍可能被恢复时保留答案。Runtime 重放同一澄清工具时 SHALL 返回原答案，不要求用户重复输入、不重复增加澄清轮数，也不得将上一问题的答案交给下一问题。

#### Scenario: 接受答案后退出
- **WHEN** 答案已被系统接受并持久化，Agent 尚未获得该答案时进程退出
- **THEN** 恢复后 Agent 收到对应问题的原答案，原请求及已确认约束保持不变

#### Scenario: 工具返回答案后退出
- **WHEN** 澄清工具已经返回答案，但后继恢复点尚未提交时进程退出
- **THEN** 再次恢复同一等待点仍返回相同答案，不重复提问、不重复扣减澄清额度

#### Scenario: 多轮答案分别恢复
- **WHEN** 一个请求先后接受多个问题的答案并在后续澄清附近退出
- **THEN** 每个问题仅能读取绑定于自身的答案，恢复不改变已发生的澄清轮数

### Requirement: 生产恢复沿用原操作

Runtime MUST 在生产准备、排队、提交、任务查询和结果返回的恢复过程中沿用原操作身份、已消耗额度和截止时间。已经提交或完成的动作不得因工具重放再次提交或重复保存产物；已知任务的确定性查询与检查继续遵守现有执行期限，未知提交继续遵守不自动重发规则。

#### Scenario: 队列暂停附近退出
- **WHEN** 一个生产暂停在入队前或入队后发生退出
- **THEN** 待提交暂停最多入队一次，已入队请求保留原顺序；不会重复占用生产名额，也不会在排队时扣生产额度或启动生产计时

#### Scenario: 队列满后恢复
- **WHEN** 请求因队列已满等待用户重试时服务重启
- **THEN** 需求与原待执行操作仍被保留，只有成功重试入队后才参与调度，不能因重建检查点自行入队

#### Scenario: 已知任务重启
- **WHEN** 请求已有持久化远端任务 ID，且未终止或到期
- **THEN** 系统继续查询该任务并检查产物，远端提交次数不增加；即使模型额度耗尽，仍在原期限内完成确定性处理

#### Scenario: 外部接收结果未知
- **WHEN** 远端可能接收了提交，但系统无法确认任务 ID
- **THEN** 系统保留该次已消耗生产额度和未知提交记录，停止自动执行，不因恢复重新提交

#### Scenario: 完成操作的结果被再次读取
- **WHEN** 已保存操作结果和产物后、后继检查点提交前退出
- **THEN** 恢复返回同一操作的实际结果，仅存在一份对应产物记录；报告事实不变，展示的剩余额度从当前持久事实计算

### Requirement: 终止和执行边界优先

Runtime MUST 在暂停提交、恢复、领取生产名额及实际副作用之前重新核对持久化的终止状态与适用执行限制。恢复点不得覆盖更晚的停止、超时、预算或用户操作时间；历史额度和绝对截止时间不得因恢复而重置。

#### Scenario: 停止与检查点提交并发
- **WHEN** 用户停止请求后，较早启动的检查点写入或恢复结果到达
- **THEN** 请求保持停止，不重新显示可继续的等待状态、不领取名额、不新增生产，保留原执行证据

#### Scenario: 恢复时已经到期
- **WHEN** 启动对账发现请求已超过生产期限或适用的生产前空闲期限
- **THEN** 系统按原规则结束请求，不重建暂停、不推进模型或生产，也不延长数据保留计时

### Requirement: 旧记录兼容恢复

系统 SHALL 保留升级前的会话、归属、预算、任务 ID、报告及文件，并对旧恢复记录进行可重复执行的兼容处理。能够证明匹配的旧恢复点 SHALL 迁移后继续；无法证明匹配的旧记录 MUST 明确失败，禁止猜测重放或重置请求。已知远端任务即使缺少可用 Agent 检查点，仍 SHALL 在未终止、未到期时按原约束完成确定性查询与检查。

#### Scenario: 旧检查点存在但旧确认标志未更新
- **WHEN** 旧会话的检查点与等待身份可验证匹配，但确认标志未保存
- **THEN** 系统不因该标志拒绝恢复，迁移后可以接受原问题的回答或保留原队列位置

#### Scenario: 旧答案已经被不可逆清除
- **WHEN** 旧检查点需要一个答案，但会话和已保存消息中均没有可验证的对应答案
- **THEN** 系统明确记录无法恢复该等待点，保留现有记录，不编造答案或要求模型猜测

#### Scenario: 旧任务已知但检查点不可用
- **WHEN** 旧请求已知远端任务 ID，但 Agent 恢复点缺失或无法验证
- **THEN** Go 执行层在原期限内完成原任务查询及技术检查，按既定交付证据生成程序说明；不为修复 Agent 状态重新生成模型

#### Scenario: 重复启动迁移
- **WHEN** 服务在旧记录迁移过程中退出后再次启动
- **THEN** 迁移不会重复增加计数、产生新会话、重复入队或删除已有模型，已迁移记录可直接使用

### Requirement: 恢复失败可观察且隔离

Runtime SHALL 为恢复拒绝、检查点损坏和迁移失败提供可区分的原因与关联事件，使用现有失败状态和执行记录向有权限的访客解释结果。单个请求的恢复错误 MUST 不阻止其他有效请求恢复；记录与导出不得包含检查点原始协议数据、密钥或匿名凭证。

#### Scenario: 单个检查点损坏
- **WHEN** 多个会话恢复时，其中一个检查点无法通过完整性或解码检查
- **THEN** 系统隔离该会话并记录明确原因，其他会话继续恢复，不因该会话重复触发无界恢复循环

#### Scenario: 数据库写入暂时失败
- **WHEN** 暂停提交遇到数据库写入错误
- **THEN** 系统不将暂停误报为成功、不产生远端副作用；存储恢复可用后通过有界恢复路径处理原暂停，重试耗尽时给出明确失败而不静默卡住

### Requirement: 恢复验证与业务验收分离

系统恢复回归 SHALL 覆盖真实运行时中断协议、关键持久化边界的强制进程退出、多会话隔离及旧数据兼容。受控模型或 Provider 的结果 MUST 明确标注为测试证据，不计作真实供应商验证或完整 Agent 行为评测通过；产物是否交付仍依据实际技术检查报告。

#### Scenario: 恢复专项通过
- **WHEN** 故障注入和恢复回归全部通过
- **THEN** 验证报告仅声明相应恢复场景通过，保留既定真实链路验证和 Agent 案例集的独立状态
