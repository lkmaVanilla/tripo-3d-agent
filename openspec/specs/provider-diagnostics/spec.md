# 供应商诊断规格

## Purpose

让供应商接入失败能够按执行、操作和请求尝试追踪，保留用户可理解的错误事实及排查所需的脱敏细节，并确保诊断记录、页面解释和日志不会改变生产提交的安全边界或泄露访问材料。

## Requirements

### Requirement: 各调用阶段保留结构化失败证据

系统 SHALL 对提交、查询、上传和下载的失败记录阶段、错误分类、发生时间、单次耗时、尝试序号，以及可取得的执行身份、操作身份、TaskID、HTTP 状态、供应商错误码和 `X-Tripo-Trace-ID`。错误分类 SHALL 区分可被证据支持的 DNS、连接、TLS、超时、取消、HTTP、供应商业务拒绝、远端任务失败、响应解析、协议缺失和本地文件／地址校验失败；无法判断时 MUST 保留未知分类，不编造原因。未收到响应的字段 SHALL 缺省或为空，不以虚构状态码或 TaskID 补齐。

#### Scenario: 提交超时没有 HTTP 响应
- **WHEN** 提交调用超时，未取得 HTTP 响应及 TaskID
- **THEN** 证据记录提交阶段、超时分类、真实耗时和尝试身份，HTTP 状态、供应商码、请求追踪标识及 TaskID 均为空或缺省

#### Scenario: 供应商返回可识别错误
- **WHEN** 接口返回 HTTP 错误或供应商业务错误，且带有可用的追踪响应头
- **THEN** 证据保留实际 HTTP 状态、供应商码和经过限制的追踪标识，既不丢弃原阶段，也不直接公开原始响应正文

#### Scenario: 响应解析或下载读取失败
- **WHEN** 查询收到无法解析的响应，或模型下载在读取过程中失败
- **THEN** 记录对应查询／下载阶段和已知 HTTP 信息，耗时覆盖本次失败过程，不把这些失败误标为生产提交失败

#### Scenario: 查询成功但远端任务失败
- **WHEN** 查询 HTTP 和业务信封均成功，但任务状态为失败并提供任务错误码
- **THEN** 证据区分本次查询成功与远端任务失败，保留真实 TaskID 和任务错误码，不误标为网络失败或提交未知

#### Scenario: 上传准备或本地校验失败
- **WHEN** 加工输入上传失败，或下载前地址检查、输入文件读取／大小检查失败
- **THEN** 记录实际阶段及错误类别；没有发生外部请求时明确表示未发出请求，不捏造 HTTP 结果

### Requirement: 逐次尝试证据不改变重试权限

系统 SHALL 保留上传准备、任务查询及文件下载过程中每一次失败的诊断，而非仅最终失败；同一操作的阶段和尝试序号 MUST 可关联，恢复后不得将新失败伪装成原记录。有限重试后的成功 SHALL 保留此前失败证据，同时将操作最终结果显示为实际成功。诊断逻辑 MUST 不增加生产提交次数，不扩展既有重试上限、预算或截止时间，也不把诊断写入错误作为重试网络动作的理由。

#### Scenario: 查询失败后重试成功
- **WHEN** 查询连续两次失败、第三次成功并继续完成原任务
- **THEN** 两次失败均保留各自耗时与尝试身份，操作显示最终实际结果，生产提交次数不增加

#### Scenario: 上传或下载重试耗尽
- **WHEN** 上传准备或下载达到其既有有限重试上限仍失败
- **THEN** 每次失败可被关联和导出，系统停止该重试过程，不为补充诊断而追加请求或刷新原执行预算

#### Scenario: 重启后继续记录原任务查询
- **WHEN** 服务重启后继续查询一个已知任务并再次遇到错误
- **THEN** 新证据仍关联原执行、操作和 TaskID，具有不与旧尝试混淆的身份，不新增生产提交

### Requirement: 诊断不能破坏已知任务和未知提交的一致性

生产结果的身份与额度 SHALL 优先遵守现行持久化和恢复协议。已取得有效 TaskID 时，系统 MUST 优先保存任务身份，再进行附加诊断记录；诊断失败不能把已保存任务退回未提交状态。对于未知提交，诊断记录失败 MUST 不撤销已经持久化的提交意图或生产额度，不触发重发。日志或执行证据存储不可用时 SHALL 报告可观察的记录失败，但不能伪称记录已完整保存或引入额外生产请求。

#### Scenario: 保存任务后附加诊断失败
- **WHEN** 已成功持久化 TaskID，而后续诊断事件写入失败
- **THEN** 任务身份保持可恢复，记录失败不导致再次提交，也不覆盖原操作的已提交事实

#### Scenario: 未知提交的诊断写入失败
- **WHEN** 提交意图和额度已持久化、外部提交结果未知，随后保存诊断失败
- **THEN** 原操作仍禁止自动重发，服务重启后也沿用这一约束，并通过仍可用的日志渠道报告诊断未保存

#### Scenario: 停止之后收到任务身份
- **WHEN** 用户停止执行后，在途提交返回有效 TaskID
- **THEN** 按现有协议保存迟到的任务身份并保留停止终态，错误或诊断处理不能把任务改成未提交或宣称远端已取消

### Requirement: 统一脱敏投影覆盖存储与输出

结构化诊断 SHALL 仅保存排查所需的受限字段及安全错误说明，并对字符串长度和外部内容设置边界。执行事件、服务器日志、HTTP 读取、WebSocket 下行及导出 MUST 不包含 API Key、Authorization、匿名凭证、上传 token、签名 URL 查询内容或敏感原始请求／响应正文。脱敏 MUST 覆盖嵌在普通错误句子内的 URL 和凭证，不以“整个字符串是否为 URL”为唯一依据。原始异常对象不能绕过这一投影被直接打印或持久化。

#### Scenario: 错误内容包含敏感材料
- **WHEN** 供应商响应或底层错误包含 Authorization、上传 token 或嵌入句子的签名下载地址
- **THEN** 执行存储、服务器日志、页面、WebSocket 和 JSON 导出均不出现这些材料，同时保留安全的分类及关联标识

#### Scenario: 外部字段异常过长
- **WHEN** 外部响应正文、错误字段或请求追踪标识长度异常
- **THEN** 诊断内容按边界截断或舍弃，不直接落盘整段正文，也不因构造诊断消耗无界内存或破坏后续输出

### Requirement: 诊断按执行持久化并遵守匿名归属

存储可用时，失败诊断 SHALL 纳入所属执行的持久事件，并在服务器日志中保留可关联的安全记录；页面刷新、断线重连和证据导出 SHALL 从相同事实读取。诊断数据的访问与保留期限 MUST 跟随现有会话及执行规则，不能因诊断增加跨会话读取或匿名越权入口。缺少新诊断的旧记录 SHALL 继续可读，显示信息未记录，不能事后编造历史错误细节。

#### Scenario: 刷新后查看已发生错误
- **WHEN** 某次调用失败已记录，用户刷新页面或通过执行导出读取证据
- **THEN** 原阶段、尝试、耗时和追踪标识保持一致，不依赖浏览器临时记录，也不重复生成逻辑失败

#### Scenario: 非所属访客读取诊断
- **WHEN** 其他匿名访客持有会话或执行身份并试图读取诊断或订阅事件
- **THEN** 系统拒绝访问，不泄露任务身份、错误证据或模型信息

#### Scenario: 兼容无诊断的记录
- **WHEN** 读取尚无结构化诊断字段的执行记录或已有测试样本
- **THEN** 原记录仍可解析，页面保留已知终态并表示没有更详细的诊断，不捏造 HTTP 状态或根因

### Requirement: 错误解释区分本地事实与远端未知状态

页面和正式说明 SHALL 依据已记录诊断及 Runtime 终态给出简明错误解释，不能将 Agent 推测作为根因。提交未知时 MUST 同时说明本地执行已停止、远端是否创建任务无法确认和不会自动重试；没有证据时不得宣称远端失败、取消、退款或没有产生费用。技术检查失败、接口失败和完整 Agent 评测未通过 MUST 分别表达；暂时失败后成功不得显示为最终失败。

#### Scenario: 超时且提交未知
- **WHEN** 本地提交超时，没有取得有效 TaskID，执行以未知提交结束
- **THEN** 用户看到提交超时、远端状态无法确认和本地未自动重试，不看到远端已取消或可安全直接重提的断言

#### Scenario: 下载失败但远端任务已成功
- **WHEN** 原任务已成功，文件下载重试后仍失败
- **THEN** 用户看到远端生成完成与本地下载失败的分别说明，不把远端任务改述为生成失败，也不展示未经检查的成功交付
