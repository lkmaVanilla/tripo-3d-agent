# Tripo 供应商接入规格

## Purpose

为现有资产生成和减面链路提供一致的 Tripo 国内站接入、可验证的部署配置与受控的站点切换边界，在保留单供应商架构的同时避免配置错误、隐式请求重发和旧任务跨站恢复。

## Requirements

### Requirement: 单部署使用明确的 Tripo V3 基址

系统 SHALL 通过 `TRIPO_BASE_URL` 配置一个 Tripo API 基址，未配置时默认使用 `https://openapi.tripo3d.com/v3`。配置 MUST 仅接受受支持的 Tripo 官方 V3 HTTPS 基址，不包含凭证、查询参数或片段；无效配置 MUST 在接受生产请求前报错，不能静默回退。一次部署中的提交、查询、上传及接入预检 MUST 使用同一基址和同一有效凭证，不能由 Agent 或会话选择站点，也不能因失败自动切换国内外站点。

#### Scenario: 缺省配置使用国内站
- **WHEN** 部署没有设置 `TRIPO_BASE_URL`
- **THEN** 提交、查询、上传和预检均使用国内 V3 基址，失败时不访问国际站兜底

#### Scenario: 显式配置在所有 API 阶段生效
- **WHEN** 部署明确配置一个受支持的官方 V3 基址并启动服务
- **THEN** 所有 Tripo API 阶段均使用该配置，不存在仍固定访问另一站点的调用

#### Scenario: 非法基址阻止生产启动
- **WHEN** 基址使用 HTTP、非官方主机、非 V3 路径，或包含凭证、查询参数、片段
- **THEN** 系统报告脱敏配置错误并拒绝启用生产能力，不发送凭证或回退到其他地址

### Requirement: 国内接入保持既有模型协议和下载边界

站点切换 MUST 保持现有 V3 文本生成和减面协议，文本生成模型保持 `v3.1-20260211`，减面算法保持 `v2.0`。供应商返回的文件下载地址 SHALL 按现有 HTTPS、公网地址校验、重定向校验与大小限制处理，不能机械替换为 API 基址，也不能向文件下载地址附加 API 凭证。接入变化 MUST 不补回未设置的面数或体积验收上限。

#### Scenario: 国内生成与减面使用各自模型版本
- **WHEN** 用户先生成模型，再明确引用本会话版本执行减面
- **THEN** 生成请求使用 H3.1 标识，减面请求使用 `v2.0` 算法标识，各自参数和真实输入来源保持现有协议

#### Scenario: 下载供应商返回的文件
- **WHEN** 国内任务成功并返回一个文件下载地址
- **THEN** 系统按原下载安全和大小限制获取文件，不改写文件主机，不发送 Tripo API 凭证，文件仍需通过技术检查才可交付

### Requirement: 接入预检独立验证网络和鉴权

部署 SHALL 提供显式只读接入预检，使用与服务一致的有效配置请求 Tripo 余额接口，并报告目标站点、网络／HTTP／供应商结果及可用的关联标识。只有收到符合接口协议的鉴权成功响应才 SHALL 判为预检通过；Key 非空、HTTP 可达和服务存活 MUST 不替代该结论。预检 MUST 不创建任务、上传资产、消耗应用生产额度或泄露凭证，也不作为每次用户请求或健康轮询的附带网络调用。

#### Scenario: 国内网络可达但鉴权失败
- **WHEN** 预检收到国内接口 HTTP 401 或供应商鉴权错误
- **THEN** 预检失败，报告网络已得到响应与鉴权未通过，阻止进入本次真实生成验收，不把更换过 Key 视为成功证据

#### Scenario: 成功的只读预检
- **WHEN** 有效国内配置获得余额接口的正常业务响应
- **THEN** 预检通过且只发起只读请求，不产生生产任务、文件上传或生产额度扣减

### Requirement: 客户端不隐式重发生产提交

对生成和减面的单次生产提交，客户端 MUST 不执行透明重试、自动站点回退或跟随 HTTP 重定向发出后继请求。提交结果不确定且没有可持久化 TaskID 时，Runtime MUST 保持已消耗额度和未知提交状态，禁止当前执行、工具重入、checkpoint 恢复或服务重启自动重发；更细的网络错误分类不得放宽该规则。已经持久化 TaskID 的操作 SHALL 继续查询原任务。明确的供应商拒绝仍按既有确定性失败和有限纠偏规则处理，不扩大纠偏预算。

#### Scenario: 提交传输失败且没有任务身份
- **WHEN** 生产提交遇到 DNS、连接、TLS、超时或响应中断错误，无法取得有效 TaskID
- **THEN** 本次操作保留未知提交和已消耗额度，不因推测请求未到达而自动重发，后续重启及重复工具调用也不新增生产请求

#### Scenario: 生产接口返回重定向
- **WHEN** 生产提交返回 301、302、303、307 或 308
- **THEN** 客户端不请求重定向目标、不转送凭证或重复请求体；本次提交在无有效任务身份时按未知结果结束并保留原 HTTP 状态证据

#### Scenario: 提交响应无法确定结果
- **WHEN** 生产接口返回 5xx、无法解析的响应或缺失有效 TaskID 的成功响应
- **THEN** 系统只保留这一次生产提交，将结果作为未知提交处理，不通过解析重试或重启补交任务

#### Scenario: 已知任务遇到临时查询失败
- **WHEN** 任务身份已持久化，查询暂时失败或进程重启
- **THEN** 系统在现有期限和查询重试边界内沿用原 TaskID，不创建替代生产任务

### Requirement: 一次性国内站切换与正常恢复分开

本次发布 SHALL 在国内预检通过后，停止本项目数据写入，备份并核实本项目实际运行数据，再按用户授权清空旧会话、执行、checkpoint、资产记录与模型文件，以空数据启用国内配置。清理 MUST 只涉及已核实的本项目运行数据，不涉及密钥、其他项目或仓库评测材料。旧国际任务不迁移、不查询、不恢复，且 MUST 不宣称远端已经取消。此重置 SHALL 是显式的一次性发布操作；正常启动、配置读取及后续升级 MUST 不自动删除数据，国内新执行继续遵守现行 checkpoint 恢复规则。

#### Scenario: 按授权以空数据切换
- **WHEN** 国内预检已通过，服务已停写，旧运行数据已完成可用备份并执行本次重置
- **THEN** 新服务从空会话和空资产目录启动，不恢复或查询任何旧国际任务，配置文件、仓库证据和其他项目数据保持完整

#### Scenario: 预检未通过时不清空历史
- **WHEN** 国内鉴权或网络预检失败
- **THEN** 本次发布不进入数据重置和真实生产验收，保留原运行数据并报告失败证据

#### Scenario: 国内新任务的正常重启
- **WHEN** 国内部署已生成新会话，之后发生普通重启或升级
- **THEN** 新数据保持原有保留与恢复规则，不重复执行历史清空，已知国内任务继续原任务查询，未知提交不重发
