# Agent 受众与执行版本规格

## Purpose

让资产制作 Agent 按 3D 创作者的实际用途理解需求，明确区分长期产品定位与当前静态资产能力。受众提示更新不扩大已开放的制作操作，也不破坏已有会话的提示版本、澄清答案与生产恢复依据。

## Requirements

### Requirement: 按实际用途理解创作者需求

新会话中的 Agent 身份与按需加载的任务指引 SHALL 面向 3D 创作者及行业从业者，不将游戏开发者或游戏原型用途设为所有请求的前提。Agent MUST 保留用户实际表达的用途、风格和限制，仅就影响当前制作决策的缺失信息进行既定范围内的澄清。

#### Scenario: 非游戏静态资产请求
- **WHEN** 用户明确要求为产品展示制作静态低模茶壶，并提供了当前制作所需的用途和技术限制
- **THEN** Agent 保留产品展示用途，不默认改成游戏道具或追问与该请求无关的游戏引擎、游戏视角

#### Scenario: 游戏用途仍然有效
- **WHEN** 用户明确要求游戏原型用静态木箱
- **THEN** Agent 保留该游戏用途，沿用静态资产制作与技术验收流程，不因受众扩大而删去用户明确的信息

### Requirement: 受众扩大不扩大当前生产权限

Agent SHALL 将当前文本到单个静态、自包含 GLB、有限减面与重新生成表达为阶段能力，继续遵守 Tripo-only、技术检查、原预算及澄清规则。Agent MUST 不将供应商潜在能力或长期方向宣告为当前已接入能力，也不得悄悄将不支持的要求改成一个不同的静态资产目标。

#### Scenario: 要求尚未接入的能力
- **WHEN** 新会话要求图片输入、已有模型导入、绑定、动画或交付后追加制作目标
- **THEN** Agent 在说明或必要澄清中指出当前版本的限制，不宣称已执行相应操作，不调用其他生产工具补齐能力，也不未经明确需求变更就以静态生成替代

#### Scenario: 普通静态请求沿用原规则
- **WHEN** 创作者提出当前支持的文本静态资产需求
- **THEN** Agent 沿用原技术上限补全、至多三轮澄清、生产预算及技术纠偏规则，生产与技术通过仍由既定执行和检查证据决定

### Requirement: 提示升级保留在途会话的执行版本

系统 MUST 记录新会话实际使用的提示与任务指引版本，并让在途旧会话继续使用与其既有恢复依据一致的受支持版本。版本更新 SHALL 不修改已接受提议、问题、答案、操作和检查点，不重置预算或期限；未知、矛盾或损坏的恢复依据仍按现行恢复规则处理。

#### Scenario: 新会话使用新受众定义
- **WHEN** 更新后的服务创建新会话
- **THEN** 该会话使用更新后的受众指引，执行记录标明实际提示版本与所加载 Skill 的内容版本

#### Scenario: 旧暂停在升级后恢复
- **WHEN** 更新前的会话处于待澄清、排队、待提交暂停或已知生产任务状态，且原恢复依据完整可验证
- **THEN** 系统使用该会话的原执行版本恢复原问题、答案或操作，纯重建不新增模型调用，不因受众更新重复提交生产或覆盖已有事实

#### Scenario: 恢复版本不可证明
- **WHEN** 会话版本与其恢复依据矛盾、版本未知或协议完整性校验失败
- **THEN** 系统明确记录恢复不可用，不修改历史版本或跳过完整性检查；已知任务仍按原期限的确定性恢复规则处理，未知提交不自动重发
