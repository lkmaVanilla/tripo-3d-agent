# Tripo 国内站发布与诊断

本次是单部署全量切换，使用国内 Key 与 `https://openapi.tripo3d.com/v3`。没有自动站点回退，也不混用国内、国际任务。一次性清空历史已由项目所有者授权；普通部署或重启绝不能照搬清空步骤。

## 配置与只读预检

`TRIPO_BASE_URL` 缺省为国内站，可显式指定官方国际站 `https://openapi.tripo3d.ai/v3`。配置必须为官方 HTTPS V3 基址，可有一个尾部斜杠；其他主机、端口、路径、凭证、查询和片段在启动前拒绝。Key 必须与所选站点匹配。提交、查询和内部文件上传共用该地址；模型下载仍走独立客户端，不发送 Tripo API Key。

三个版本名称表达不同含义：API 协议为 **V3**，文本生成使用 **H3.1 / `v3.1-20260211`**，减面使用独立算法 **`v2.0`**。本次没有迁移 V2 API，也不修改 DeepSeek `deepseek-v4-pro`、Skill 或执行协议版本。用户未设置的面数／体积验收上限仍为空。

开发环境在已有 `.env` 下运行：

```sh
go run ./cmd/check-tripo
```

部署环境先构建 `cmd/server` 和 `cmd/check-tripo`，在与服务相同的工作目录、用户和有效环境中运行后者。预检仅 GET `/account/balance`，不创建数据库、Run、上传或生产任务。退出 0 表示网络、HTTP 和余额响应业务协议通过；非 0 时只输出安全诊断。Key 非空、首页就绪或 HTTP 200 均不能单独证明鉴权成功。

输出不含 Key、完整余额响应或账户余额数值；发布时另外以同一有效凭证只读确认余额足够本次计划调用，仅记录是否足够，不把账户信息提交到仓库。预检通过仍不等于上传、CDN 下载或生产成功。

## 发布顺序

1. 运行 Go 全量测试、race、vet、网页行为测试和构建，记录结果。留存候选二进制 SHA256、`go version -m` 的源 revision 和 dirty 标记、对应源差异摘要；未提交候选不能冒充已有提交。
2. 用 `systemctl show` 核对 `tripo-agent.service` 的执行文件、工作目录、运行用户及 `EnvironmentFiles`。读取运行进程实际环境，比较 Key 是否与目标配置相同，只输出一致性布尔值。禁止打印完整环境、配置或带认证的请求。
3. 从有效 `DATA_DIR` 与实际工作目录解析绝对路径，核实目录下 SQLite、checkpoint、会话、资产和模型文件。清理目标必须是本项目专用目录，不能是 `/`、仓库、配置目录、符号链接指向的未知位置或其他应用数据目录。只读统计活动执行和任务身份。
4. 在 ECS 上使用候选预检程序、服务实际 Key 和目标国内基址验证接入及额度。**预检失败不停止旧服务、不清理旧数据、不试发付费任务。** 不使用旧国际任务探测国内站。
5. 暂停本应用入口并正常停止服务，确认 MainPID 退出且没有其他进程写该数据目录。记录停服时间、原二进制、受保护配置备份和数据路径。入口暂停只影响本项目，其他站点保持原状。
6. 在受限权限目录备份停写后的整个运行数据，包括 `tripo.db`、存在的 WAL/SHM、全部模型文件；检查 SQLite `integrity_check`、`foreign_key_check`，比对逐文件 SHA256、路径、数量与字节数。备份在 ECS 私有目录保存，禁止提交 Git。备份无法验证时不清空。
7. 将核实过的完整旧数据目录移出活动位置，创建相同路径、属主及受限权限的空目录。配置、密钥、程序、仓库验收材料、其他项目不在清理范围；不要零散删除表或只删数据库留下资产文件。保存清空前后清单。
8. 安装候选版本，在服务环境文件显式写入国内基址，保留其余配置。启动单个服务，核对实际二进制 SHA256／revision、有效基址、Key 加载一致性，并再次运行只读预检。确认活动库没有旧会话和 TaskID，没有查询旧国际任务。
9. 受控窗口内按下面的真实链路验收。新库启动后做普通重启，验证会话、版本、文件、TaskID 均保留；清空仅是人工发布步骤，程序启动路径没有清理开关。完成核对后恢复普通访问。

## 真实验收与停止条件

验收一次文本生成和同会话一个显式引用 v1 的减面目标，通过真实网页聊天、真实 DeepSeek 与国内 Tripo 执行。按用户于 2026-09-19 确认的验收口径，允许 Agent 在既有预算内依据已保存的不达标技术报告自动纠偏，逐次记录实际生产次数。生成请求明确静态资产、用途和风格，不强制给产品恢复默认验收上限；v1 完成后读取实测面数，选择供应商合法且低于实测值的目标。

保存每次生产的脱敏 Run／Operation／TaskID、版本 ID、父版本、技术报告、正式结果及关联事件。确认所有候选的自包含 GLB 均可下载、网页加载可交互，v1 文件内容不变，v2 使用的上传输入哈希与 v1 相同，后续纠偏候选的父版本与实际输入哈希对应，最终交付实测面数降低并满足已保存的验收上限。未达标候选和原报告保留。刷新、重新建立 WebSocket、下载和导出都不能增加生产提交；不同匿名身份无权访问。预览只验文件加载和交互，不做视觉质量评测。

遇无 TaskID 的未知提交立即停止本次验收，不自动重发，不为了报告通过再造一个等价 Run。明确失败也如实记录，额外人工重跑须另记原因和范围。本次真实冒烟不代表完整 Agent 案例集重新通过。

## 回退边界

国内新生产开始前，可以停服恢复旧程序、旧配置和完整旧数据备份；这不保证旧国际网络问题消失，也不应自动查询旧国际任务。

一旦有国内新任务或用户新输入，禁止用旧国际库覆盖国内数据。先停写并备份当前国内状态，保留 TaskID、未知提交、预算及文件，优先在国内配置下向前修复。必要的代码回退必须兼容当前数据并继续显式使用国内站。没有自动跨站数据回滚。

## 安全诊断字段与解释

每次失败产生 `provider_call_failed` 事件和同载荷进程日志；当前操作保存 `last_failure`，成功恢复后清除当前摘要，历史失败保留。诊断失败不会回滚提交意图、扣额或 TaskID，也不会触发供应商重试。日志 `recorded=false` 表示持久化失败，不能宣称数据库包含该条证据。

| 字段 | 含义 |
| --- | --- |
| `schema_version`、`provider` | 诊断载荷版本 1、供应商 tripo，与 Agent 执行版本无关 |
| `phase` | submit / query / upload / download；独立预检为 preflight |
| `category`、`cause_code` | 已观察到的 DNS、连接、TLS、超时、取消、HTTP、供应商拒绝、远端任务失败、解析、协议或本地校验分类；无证据时 unknown |
| `request_started` | 已进入请求调用；不证明远端收到请求或完成生产 |
| `occurred_at`、`duration_ms` | 单次调用完成时间与耗时；不是整个 Run 耗时 |
| `http_status`、`provider_code`、`task_error_code` | 可选的 HTTP、API 信封码及远端任务失败码；没有证据时省略，不能将三者混为一谈 |
| `provider_trace_id` | 通过字符和长度白名单的追踪标识；没有或不安全则省略 |
| `run_id`、`operation_id`、`task_id` | 归属身份，未知提交不伪造 TaskID |
| `attempt_id`、`retry_group_id`、`attempt` | 单次尝试、局部重试组、尝试序号；上传沿用持久化准备尝试预算，其他局部重试组重启后重新编号 |
| `submission_unknown`、`message` | 远端提交结果是否未知及 Runtime 可公开说明；均不授予重试权限 |

原始响应正文、任意异常文本、Authorization、Key、上传 token 和签名 URL 不属于诊断字段。底层 cause 仅用于进程内 `errors.Is/As`，公开说明从固定语义重建。HTTP、WebSocket、执行导出与会话导出共用同一份已保存事实；没有诊断的历史记录保留兼容说明。

带凭证 API 使用 HTTP/1.1、禁止自动重定向，生产请求不提供可重放的请求体。这样也排除了 Go HTTP/2 在连接尚未写入时内部换连接重试的路径，单次尝试的记录边界可由应用控制。查询、下载和上传的应用层有限重试保持不变；独立模型下载保留原协议协商及受限重定向策略。

用户看到的提交未知只表示本地已停止、无法确认远端是否创建、没有自动重试；不承诺远端取消或退款。远端任务成功但下载失败明确标为尚未交付。最终交付优先于中间失败；迟到错误不将已停止 Run 改成运行中。
