# MVP 自动产物验证仅采用技术检查

> 默认上限条款对新聊天执行已由 [ADR 0023](0023-optional-asset-acceptance-limits.md) 替代；以下保留历史决定及旧执行兼容语义。
Agent 的结果纠偏需要可核验的产物反馈。MVP 选择仅基于模型文件及可读取元数据进行确定性技术检查，排除视觉检查，以控制验证范围和实现成本，并避免增加视觉模型调用及其误判处理。

这一决定保留基于技术检查反馈的有预算上限的纠偏，但不自动判断物体类别、风格、材质观感等视觉要求是否满足。用户的视觉要求仍需保留在资产意图和生成描述中；技术检查通过只能支持已检查技术项的结论，不能据此宣称全部需求已满足。

MVP 技术检查限定为以下三类：

- 文件有效性：实际模型文件可解析，且包含非空网格，同时核对首版声明的产物支持范围。
- 几何规模：实际文件内所有网格的总三角面数不超过明确上限。
- 文件体积：实际文件大小不超过明确上限。

几何规模和文件体积的上限来自用户要求或向用户明确展示的系统默认值。首版默认不超过 5,000 个三角面、文件不超过 10 MiB（10,485,760 字节），只补全用户未提供的字段，用户明确要求优先。

生成前向用户展示采用的默认假设，并将最终验收上限记录到当前请求。进入生产执行后固定本次上限，后续修改全局默认配置不影响已有请求。Agent 可调整生成目标面数，但不得改变验收上限。

这两个数值沿用首条木箱演示方案，作为可配置初值，后续依据真实产物的检查结果调整默认配置。检查必须读取实际产物，不以生成请求中的参数代替实测结果。

首版产物限定为自包含的静态 GLB 和三角面网格，见 [ADR 0012](0012-glb-artifacts-and-controlled-parameters.md)。遇到压缩网格、外部资源依赖或不支持的格式时，报告不支持或无法验证，不能将其记为检查通过。

此决定限定的是自动产物验证范围，项目简报中的 Agent 自动评测要求仍然保留。案例集评测和单次执行评测的职责及指标类别见 [ADR 0007](0007-scenario-based-agent-evaluation.md)。
