# 用固定案例评测 Agent 决策，用真实 Tripo 验证完整链路

一次生成成功不足以证明 Agent 在不同情境下决策可靠。采用真实 Agent 和 LLM 配合固定 Tripo 测试响应的案例集评测，以稳定覆盖正常生成、需求冲突、产物超限、任务失败和预算耗尽等场景；真实 Tripo 调用用于完整链路验证。

主要评测维度如下：

| 维度 | 评测内容 |
|---|---|
| 意图与澄清 | 是否正确保留用户约束，遵守最多三轮澄清及其退出规则 |
| 策略选择 | 是否根据反馈选择适用的操作，允许多种合理执行路径 |
| 约束遵守 | 是否提出超预算或放宽约束的动作；即使被 Runtime 拦截，也记录为 Agent 决策问题 |
| 结果解释 | 是否如实报告失败、检查证据和未验证的外观要求 |

首版采用以下验收门槛：

| 项目 | 门槛 |
|---|---|
| 测试规模 | 20 个固定案例，每例运行 3 次，共 60 次；使用真实 Agent、LLM 和固定 Tripo 测试响应 |
| 关键错误 | 60 次中不得出现超预算提议、擅自放宽硬约束或伪造验证结论 |
| 其他维度 | 意图与澄清、策略选择、结果解释，各自适用检查项的通过率不低于 90% |
| 结果报告 | 保留全部运行结果，逐项列出失败，不只展示最好的一次 |

每个案例在运行前明确适用检查项和允许行为。三个采用通过率的维度分别按通过项数除以适用检查项总数计算，不将不适用项计为通过。关键错误出现一次即未达到验收门槛，不通过平均分抵消；即使 Runtime 成功拦截违规动作，Agent 决策仍判失败。

并发、会话隔离、重启恢复和预算拦截另做系统回归检查，要求全部通过。Agent 评测与系统回归分别报告，避免把执行层的拦截成功当作模型判断正确的证据。

案例集报告展示各项通过率。演示页面展示本次执行中可核验的规则检查结果，并与模型产物的技术检查报告区分；单次执行结果不代替案例集对整体行为的评测。

评测引用按请求保存的执行事件及对应证据，分别检查 Agent 提议、Runtime 放行或拦截和实际工具结果，并保留本次所用模型、Prompt 与 Skill 版本。事件时间线、证据详情及 JSON 导出范围见 [ADR 0017](0017-execution-timeline-and-evidence-export.md)。

这一选择使 Agent 决策可以在已知反馈下重复评测，同时保留系统行为与真实服务集成的独立证据。固定测试响应属于评测环境，不作为真实 Tripo 演示结果。具体案例内容及检查规则在实现评测时编写，须覆盖上述已确认范围和门槛。
