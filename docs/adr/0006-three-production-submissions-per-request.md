# 每次资产请求最多一次首次生成和两次纠偏提交

Agent 需要足够的尝试空间来展示根据反馈调整策略的能力，同时需要明确的停止边界。单次资产请求采用首次生成一次、纠偏最多两次的次数预算；减面和重新生成共用纠偏额度，总计最多三次生产操作提交尝试。

每次生产操作按提交尝试计数，失败或结果未知也占用额度。查询状态、下载和技术检查不占生产额度，受执行截止时间及独立的重试与单次操作超时限制；后两者的具体参数在实现阶段确定。

Runtime 强制执行次数上限，Agent 不得自行增加额度。额度耗尽后禁止提交新生产任务；已提交的任务仍继续等待和验收，并受独立超时限制，不能因为额度用完而跳过最终检查。

预算需要持久化，重启与恢复不得重置已消耗额度。提交结果未知时保留额度并停止自动执行，不自动重复提交；恢复边界见 [ADR 0009](0009-recover-known-executions-without-resubmission.md)。

例如，首次生成、减面、重新生成合计三次生产操作，随后仍需执行最终检查。检查通过可交付结果；仍未通过则说明未满足的技术要求和停止原因。

这一预算约束的是生产提交次数，不等同于模型决策循环次数、执行时长或固定金额预算。单请求默认最多 20 次模型调用、首次生产提交后最多执行 30 分钟，以及用户主动停止的语义，见 [ADR 0013](0013-execution-limits-and-local-stop.md)。
