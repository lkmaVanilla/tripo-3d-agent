# 会话承载独立执行和不可变版本，整体保留

状态：已采纳，随 `add-conversational-asset-workspace` 实施；验收状态以阶段验证记录为准。

采用 Conversation → 多个 Run → 生产操作与 AssetVersion。保留原 Session 的物理 ID、检查点和预算，将它解释为 Run；旧入口创建 v2，聊天新入口创建 v3，原 v1/v2 的模型协议不随升级改变。相比复用已结束的 Session，这个结构增加一层归属，却避免重置旧预算、覆盖结果和让旧检查点恢复到另一个目标。

一个会话围绕同一资产主题，最多一个活动 Run。正式新消息使用幂等身份原子创建 Run；澄清答案绑定原 Run、问题和暂停代次。停止先持久化并取消本地执行，worker 退出后才释放活动指针；这不等于远端任务已取消，不提供停止后恢复或取回任务。运行或退出期间只保留输入草稿，不排队后续制作目标。

引用必须由用户明确选择本会话的一个版本。加工实际消费哪个版本，就记录哪个几何父版本；文本再生成只记录上下文引用。新产物追加版本，旧文件和报告不变。保存的 GLB 在加工前核对身份和摘要后内部上传给 Tripo，临时文件 token 与语义输入分别保存；上传尝试跨重启最多三次，生产提交未知时绝不刷新输入重发。这个内部适配不开放用户模型导入。

引用版本的需求先保存差异草案，再在同一次工具调用内冻结正式意图，两个事务以草案内容身份关联。这样既能在正式保存前展示差异，又不增加用户确认或模型轮次；草案不能触发生产，中途退出后可幂等重放。Go 补回未提供的来源字段，显式改变的语义仍由 Agent 判断。

公开聊天是业务事实的持久投影，消息、版本及事件同事务提交；全局事件游标跨 Run 补读。HTTP 接受命令，WebSocket 只下发状态。Agent 的解释保留来源，正式交付事实来自程序核验。纯解释不产生新模型，也不消耗生产额度。

空闲会话自最后 Run 的持久化结束时间起整体保留 7 天。到期前正式接受新目标保护所有历史数据，新 Run 结束后重算期限；浏览、下载、心跳和草稿不续期。活动或退出中的 Run 不清理。迁移不改旧 Run 的 Ended/Expires；清理先标记整段不可访问，再幂等删除关联记录和目录，避免旧文件先于后续目标消失。
