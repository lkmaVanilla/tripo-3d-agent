# 同一资产的会话支持持续创作，目标完成与会话结束分开表达

资产制作助手的长期交互需要承接已有资产结果，用户选择在同一会话中持续提出后续制作目标。例如，在相应 Tripo 能力完成接入后，用户可先生成角色，再于原会话要求骨骼绑定和动画制作；一次目标完成不自动结束整个创作会话。

相比每次加工都建立独立会话，这一选择让用户可以沿用当前资产和必要的创作上下文，减少重复说明加工对象与背景。代价是会话的交互生命周期必须与单次目标的执行状态区分，并在后续设计中明确资产结果引用、目标间预算划分、会话关闭及数据保留的规则。本决策不预先确定这些实现方式或数值，也不允许通过重开旧请求重置已消耗预算。

[ADR 0011](0011-request-context-and-readonly-skills.md)、[ADR 0014](0014-anonymous-sessions-and-concurrent-access.md) 中“一会话一请求”和当前请求 Context 的限制继续适用于现有 MVP；它们不再代表长期交互上限。同一资产会话中的上下文承接不扩展为跨会话长期记忆、RAG 或多个 Agent 协作。不同访客与不同会话的访问隔离继续适用。

[ADR 0018](0018-anonymous-session-retention-and-expiry.md) 的现行保留期限保持不变；长期持续协作何时关闭会话、何时开始计算数据保留期，需在相应能力实施前明确。本次只记录产品与领域边界，当前实现仍在一次请求交付或终止后结束执行，尚不支持追加新目标。
