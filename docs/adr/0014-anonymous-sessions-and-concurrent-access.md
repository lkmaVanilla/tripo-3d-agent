# 支持匿名创建多个会话及并发访问

适用范围：以下“一会话一请求”映射约束当前静态资产 MVP。长期同一会话持续创作的方向见 [ADR 0021](0021-continuous-asset-collaboration.md)，本决策中的匿名归属与并发隔离要求继续适用。

首版需要让访客直接建立会话并使用 Agent，采用无需注册或登录即可创建多个会话、支持并发访问的产品形态。不同会话可以同时交互和推进各自的资产请求，不采用部署级访问口令作为统一入口，也不将全服务限制为一个未结束请求。

一个会话只承载一个资产请求，围绕一个资产需求包含多轮澄清、首次生成、纠偏以及最终交付或终止。制作另一个资产时新建会话，例如制作木箱与制作路灯可以在两个会话中同时执行。

会话内的澄清、首次生成和纠偏共用同一请求的 Context、预算和执行记录；不能将纠偏视为新请求来重置额度。这一边界使会话历史、资产结果和预算保持明确对应，也延续了 [ADR 0011](0011-request-context-and-readonly-skills.md) 中 Context 围绕当前资产请求的范围。首版不在同一会话中组织多个独立资产需求。

单 Agent 架构保持不变：每次资产请求由一个 Agent 负责决策，不引入多个 Agent 协作。不同请求可以并发执行；同一请求内部的生产操作仍串行，使下一次纠偏依据上一次技术检查结果。

会话分别组织对话与执行记录。各资产请求的 Context、预算、检查点、Tripo 任务状态和进度事件必须隔离；既定的澄清轮次、生产次数、模型调用次数和执行期限继续按请求分别计算。

这一选择允许访客直接体验和同时使用应用。相应代价是首版必须处理匿名会话的访问与恢复、并发执行状态隔离和服务容量，不能依赖单操作者或全服务串行的假设。

匿名访问与恢复采用浏览器持有凭证、服务端校验会话归属的方案，见 [ADR 0015](0015-browser-held-anonymous-credentials.md)。首版采用最多 3 个生产阶段请求和最多 10 个按序等待请求，队列已满时提示繁忙并保留需求，见 [ADR 0016](0016-bounded-production-concurrency-and-queue.md)。上述需求不改变已确认的 Go 单服务与 Eino 单 Agent 架构，也不自动引入账号系统或通用 Agent 平台。
