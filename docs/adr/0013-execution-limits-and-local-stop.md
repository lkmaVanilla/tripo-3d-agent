# 持久化执行上限，并明确本地停止语义

生产提交次数上限不能限制模型反复决策或后台任务长时间等待。首版分别控制模型调用次数、生产后的执行时长和用户主动停止，并由 Go 应用持久化及强制执行这些边界。

| 边界 | 行为 |
|---|---|
| 单请求累计最多 20 次模型调用，失败及重试尝试也计数 | 停止模型决策和新增生产；已提交任务仍在执行期限内查询、检查，由程序输出结果说明 |
| 从首次生产提交开始，最多执行 30 分钟 | 包含轮询、下载、检查和重启停机时间；到期停止本地自动执行 |
| 尚未开始生产，连续 24 小时无用户操作 | 结束请求，排队中的请求不再自动启动 |
| 用户主动停止 | 停止本地后续执行，保留已有结果、Tripo 任务 ID 和执行记录 |
| 浏览器刷新或服务重启 | 不重置调用计数和截止时间，不自动恢复已终止请求 |

等待用户澄清及首次生产前排队的时间不计入上述 30 分钟。20 次和 30 分钟是首版可配置初值，后续依据真实演示耗时调整；当前请求按已保存的上限和截止时间执行，Agent 不得自行延长。

排队不消耗生产提交额度。用户停止排队请求后，该请求不再自动开始；排队及生产名额规则见 [ADR 0016](0016-bounded-production-concurrency-and-queue.md)。

生产前的无操作期限独立于首次生产后的 30 分钟执行期限，适用于等待澄清和排队等尚未开始生产的状态。后台轮询和心跳不视为用户操作，重启不重置等待期限；因此结束的线上会话自结束起保留 7 天，见 [ADR 0018](0018-anonymous-session-retention-and-expiry.md)。

模型调用额度耗尽与执行终止分开处理。额度耗尽不跳过已提交任务的确定性查询与验收，也不要求额外调用模型才能生成最终说明；超时或用户主动停止则结束本地自动执行。模型调用计数、绝对截止时间和终止状态随原请求持久化，旧检查点不能覆盖终止状态或重置限制。

本地停止不能被展示为 Tripo 远端任务已经取消。外部任务标识与已知结果继续保留；服务重启时先核对终止状态和截止时间，再按 [ADR 0009](0009-recover-known-executions-without-resubmission.md) 决定是否恢复。

这一选择使 Agent 循环、异步等待和用户控制都有明确停止边界，同时保留预算耗尽后对已提交产物的验收能力。代价是必须在应用中维护跨恢复的计数和截止时间，不能只依赖 Eino 的单项循环限制或进程内取消信号。
