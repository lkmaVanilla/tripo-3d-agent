# SQLite 保存执行状态，本地持久目录保存模型

单 Go 服务需要保存可恢复的请求状态、预算、Agent 检查点和执行证据。采用 SQLite 保存结构化记录及检查点，下载的模型文件保存到本地持久目录，数据库记录模型路径和元数据。

| 存储 | 保存内容 |
|---|---|
| SQLite | 匿名凭证校验信息与有效期、会话归属、会话与请求关联、用户操作时间与数据到期时间、对话、意图、预算、排队状态与顺序、生产阶段状态、模型调用计数、执行截止时间与终止状态、生产操作、Tripo 任务 ID、Eino 检查点、执行事件、模型与 Prompt/Skill 版本及评测结果 |
| 本地持久目录 | 下载的模型文件 |

预算扣减、生产操作记录和相关事件在同一数据库事务中保存。数据库事务不覆盖 Tripo 调用或模型文件写入；应用仍按 [ADR 0009](0009-recover-known-executions-without-resubmission.md) 核对恢复状态，未知提交保留额度且不自动重发。

这一选择将本项目的状态集中在应用本地，适合已确认的单服务部署形态。数据库与模型目录都需要配置持久磁盘，恢复能力依赖这些数据在服务重启后仍然存在。

线上匿名会话的数据及模型文件在会话结束后保留 7 天，到期删除；固定评测用例与正式评测报告独立保存，见 [ADR 0018](0018-anonymous-session-retention-and-expiry.md)。

参考：[SQLite 官方适用范围](https://www.sqlite.org/whentouse.html)。具体 Go 驱动、数据库连接参数和目录布局在实现阶段确定。
