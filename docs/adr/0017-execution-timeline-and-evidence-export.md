# 按请求保存事件时间线，展示并导出可核验的证据

公开演示和 Agent 评测需要能够追溯需求、决策与实际结果。每个资产请求采用按顺序排列的事件时间线，页面默认展示摘要，展开查看证据详情，并支持导出完整的脱敏 JSON 执行记录。

| 内容 | 记录范围 |
|---|---|
| 需求与计划 | 原始需求、澄清、确认意图、默认假设及计划变化 |
| Agent 决策 | 选择的动作、简短依据、引用的检查结果、加载的 Skill |
| Runtime 处理 | 动作放行或拦截、预算变化、排队、恢复和停止 |
| 工具执行 | 脱敏后的参数与响应、任务 ID、异步进度、耗时和错误 |
| 产物与评测 | 实测面数和体积、检查结论、评测规则及对应证据 |

同时记录本次使用的模型、Prompt 和 Skill 版本。每条事件归属特定请求，保留稳定顺序，并通过关联记录连接决策、执行与检查证据。

Agent 提议、Runtime 放行或拦截、实际工具调用及其结果分别记录。计划和简短决策依据属于 Agent 输出，预算变化、实际调用和检查结果由执行层记录，不能将前者当作后者的证据；被拦截的违规提议仍保留供评测判定。

持久化记录为页面展示、断线重连、JSON 导出和评测提供共同依据。界面默认摘要与按需展开控制前端范围，详细记录仍可核验。时间线及导出均按匿名会话归属校验访问权，密钥和访问凭证不进入对外记录。

这一选择让观众可以核对 Agent 打算做什么、Runtime 如何处理以及工具实际返回了什么，也让失败案例能够回溯到具体证据和版本。代价是需要统一事件归属、顺序、关联与脱敏，不能仅保存 Agent 最终生成的一段过程总结。
