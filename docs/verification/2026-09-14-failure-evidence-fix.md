# 缺输出反馈的证据边界修复

此前局部诊断中的 `missing_output/3` 仍有关键解释错误：两次收到成功但无模型地址的反馈后，Agent 断言调整提示词或参数不能纠正。主动提前结束合法；错误在于把未经诊断的排除结论写成事实。历史记录和评分保持原样。

## 实现

- `production.go` 在实际查询成功且缺地址的分支使用内部错误类型，通过 `errors.Is` 仅为 v3 持久化 `missing_model_output`。供应商返回的同字面错误不会被识别为这项观测；旧 v1/v2 的错误文本和工具反馈不改变。
- `conversation_model_context.go` 统一生成 `failure_evidence`，供工具反馈和后续模型上下文使用。它包含操作/任务身份、查询成功、模型地址缺失、没有检查文件、原因未知、参数影响未排除、重试效果未知。
- 决策说明将“这次选择结束”与“已经证明无法纠正”分开。未取得的该文件不能被检查或减面；是否继续生产仍由固定目标、剩余预算、期限和工具门禁共同决定，不增加另一套允许动作计算。
- 纠偏 Skill 和 v3 收尾参数的说明要求依据这一证据解释。原始正文与工具参数完整留痕，不增加第二个语义模型，不用关键词过滤、自动改写或 Go 正式报告掩盖模型错误。

## 验证范围

新增受控测试覆盖包装错误与同字面普通错误、v1/v2 兼容、落库重放、证据投影一致和最新预算；真实 Eino 受控路径验证缺文件后的下一次决策实际获得类型化证据，仍可在预算内再次生成或主动停止，未知提交保持仅一次提交。

本地测试证明数据来源和执行边界，不证明真实模型解释已通过。真实模型诊断及完整批次遵守[预声明](../evaluations/2026-09-14-final-evaluation-plan.md)，结果与系统回归分别记录，不混为同一个通过结论。
