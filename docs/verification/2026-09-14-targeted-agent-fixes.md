# 第三批评测问题的针对性修复

修复范围是[第三批完整评测](../evaluations/2026-09-current-v3-revised-evaluation-results.md)定位的模型动作协议与解释依据问题。保留静态资产、技术检查、单 Agent、原 Run 预算和历史版本隔离，不增加视觉检查或新生产能力。第三批原始证据和成绩保持不变；修复后的真实模型整批评测尚未运行，任务 `10.6` 和 `11.2` 仍未完成。

## 模型动作协议

v3 对非空正文但不调用工具、同次响应调用多个工具两类错误，允许一次协议纠正。两次仍不合规则以模型动作错误结束；不根据正文猜测问题、生成参数或结束选择，不执行被拒绝批次中的任何工具。空响应、接口错误及缺少有效调用身份的批量响应直接失败。

每次实际模型请求都在发送前重新检查并扣减原 Run 的模型预算，停止、期限和 20 次累计上限仍生效。一次纠正最多增加一次模型请求，不刷新生产额度、澄清轮数或期限。纠正之前的普通问句不算澄清；只有模型改为合法 `ask_user` 并保存 checkpoint 后，才实际等待用户。

纠正消息仅用于提供方请求副本；Eino 原始输入、正式 History 和恢复种子使用最终接受的响应。批量错误的每个调用有明确“未执行”回执，原始响应的思考协议字段完整保留；恢复重建不产生额外请求。`agent_proposal`、`runtime_blocked`、`model_protocol_retry` 与逐次 `model_call` 保存实际经过。

没有采用强制 `tool_choice=required`：当前 DeepSeek 思考模式不支持该设置，官方说明会返回 400；SDK 能序列化参数不等于提供方支持。本轮保持既定模型及思考模式。[DeepSeek Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)

## 解释依据与纠偏指引

- 模型输入增加 `explanation_basis`，区分检查能力与本次实测：可检查文件有效性、面数和体积，不表示已经检查了外观或诊断了供应商原因。实际数值仍从对应报告读取。
- v3 指令及四个 Skill 区分用户要求、公开默认、实测事实和未知事项。正文、计划、假设、操作理由及最终解释都受这些边界约束；不能通过结尾免责声明抵消之前的确定性断言。
- 明确 `goal_kind` 是固定目标，操作类型只是其中一步。生成目标内的减面纠偏不会把目标改成减面；在原预算和工具条件内仍可再次生成或停止。明确的减面目标仍不能改为生成。
- 缺文件只说明未取得可检查产物；不能由此证明调整提示词或参数无效。参数选择不保证细节质量、用途符合性或文件体积。
- 判断独立资产时只说明已知的主题变化，不臆造用户未提供的用途、风格或硬约束差异。

这部分修复提供更准确的事实边界和动作指引，不是通用语义验证器。正式事实仍由 Go 根据报告构造，原始说明继续独立评测。

## 评测证据完整性

协议纠正前的被拒绝响应不会进入 Eino 正式 History，因此评测改从持久化 `agent_proposal` 事件提取全部响应元数据，按 `event_seq` 定位。未返回 usage 时保留缺失状态，由离线汇总拒绝；不以零代替未知用量。

原有 `runtime_blocked_proposal` 与单工具检查继续把被拒绝提议记为策略失败，后续正确收尾不能抵消它。新增受控回归同时检查最终动作可成功、原始错误仍失败、两次响应用量都保留。后续批次的 manifest 明确记录纠正规则和元数据来源；旧批次不重新计算或覆盖。
