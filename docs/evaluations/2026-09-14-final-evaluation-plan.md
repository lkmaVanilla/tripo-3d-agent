## 修复与诊断

当前缺文件反馈只记录错误文字，模型多次将主动停止误解释为已经证明提示词或参数不能解决。新增仅用于当前 v3 的 `missing_model_output` 类型化观测，由真实缺地址分支持久化；工具结果与模型上下文共用 `failure_evidence`，区分查询状态、文件未检查、原因未知、参数影响未排除及自主停止。保持现有门禁和未知提交保护，不增加语义判官、关键词过滤或自动改写原始解释。

对原 `missing_output` 场景运行三次独立诊断，采用原输入、固定 Provider 和原评分。三次全部自动/语义通过且零关键错误才启动完整批次；否则保留证据并定位问题。诊断不能代替完整验收，历史的 `product/1` 和 `missing_output/3` 记录不改写。

## 完整批次

- 当前 `asset-agent-v3`，真实 `deepseek-v4-pro`、high thinking、8192 输出上限；固定本地 Provider 和合成 GLB，不调用真实 Tripo，不使用真实用户资产。
- 固定基线 20 类 × 3 次、连续创作 8 类 × 3 次，共 84 个目标；每目标原 20 次模型/3 次生产额度不变，整批最多 1680 次模型调用。
- 启动前记录源码摘要，批次期间冻结代码、提示和案例；新目录保存全部请求、原始提议、工具反馈、事件、响应元数据和每例审核。保留被 Runtime 拦截或纠正的错误。
- 每例每个适用维度一个综合项；意图、策略、解释各维度在基线与连续组均至少 90%，关键错误为零。未知提交由 Runtime 直接结束、模型没有反馈后解释机会时，沿用既有解释不适用口径；其他缺失解释不豁免。
- 审核涵盖所有原始正文及工具参数，不能用 Go 正式报告补足模型说明。数值和状态依对应证据；缺少视觉验证的确定外观结论、未诊断因果的确定归因或排除，仍按既有关键错误处理。
- 不根据分数删例或选择性补跑，不以更换评分门槛达成 47/47。若未通过，报告真实结果并保持未完成项。
