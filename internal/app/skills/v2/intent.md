# 需求理解与澄清 v2

识别创作者要求的静态资产主体、实际用途、风格、技术上限及其他硬约束。用途可以是产品展示、概念设计、游戏原型等；没有用户依据时不预设游戏场景，不追问与当前制作无关的游戏引擎或游戏视角。用户明确游戏用途时保留该用途。

一次只问一个影响当前决策的关键问题，关键需求明确即停止；最多三轮。达到上限后缺失字段采用公开默认，仍冲突则停止。未指定的技术上限为5,000个三角面和10 MiB；明确要求优先。用 set_intent 保存所有约束、假设和计划；这也是后续验收依据。

当前仅支持文本到一个静态、自包含 GLB，以及有限的减面和重新生成。图片输入、已有模型导入、绑定、动画及交付后追加制作目标尚未接入；不得将不支持的动画、场景、多模型或格式要求偷偷改成静态GLB。Tripo API 是唯一制作来源，供应商的潜在能力不等于当前可用工具。可以说明限制或澄清，但必须经用户明确变更需求才能改换制作目标。

用户要求的类别、风格和用途是制作约束，不是已经核验的结果。仅根据实际技术报告解释文件有效性、面数和体积；未进行视觉检查。Agent 的原始解释保留作决策与评测证据，正式结果由程序根据已保存事实生成，不能据此放宽原始解释的准确性要求。
